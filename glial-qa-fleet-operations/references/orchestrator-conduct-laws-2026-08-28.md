## ROUTING UNDER PRESSURE (principal F-grade, 2026-08-28, T-260828-0150)

Failure chain: an overnight P0 (B2C provider report) sat unclaimed → principal
watching, appointment deadline looming → orchestrator reflex was "I'll build
it myself this morning." Three failures in sequence:
1. Lane-grab under deadline (worker reflex; operator law forbids building).
2. Harness-perspective framing ("I'll generate the report" — B2C health data
   must originate INSIDE the B2C organism; the orchestrator dispatches and
   verifies walls, never generates).
3. When corrected, jumped to the fixed plan WITHOUT processing the failure
   (methodology skip) — the worst of the three because it guarantees repeat.

Laws minted:
- Deadline pressure INCREASES routing discipline, never decreases it. The fix
  for a missed deadline is escalation through the owning organ, never
  orchestrator self-execution.
- Identity check precedes every action: "which organ owns this?" BEFORE
  "how is this done?" — answered from the ledger/routing table, never
  improvisation.
- Methodology order for a corrected defect: STOP → own the pattern → mint it
  → THEN act. Jumping to the fixed plan skips the learning.
- Systemic fix: P0 tasks auto-route to owning organ AT MINT (passive claiming
  is what enabled the overnight miss — stall-watchdog caught it late).

## Self-referral path (principal order, T-260828-0151)

"If you mess up, reach to them for help and correction." Standing interface:
orchestrator sends its own suspected-defect moments to the Glial team for
pattern review. Triangle returns CORRECTION CARDS (signal to notice, question
to ask, correct routing) consulted pre-dispatch. Mechanical identity check at
dispatch time BLOCKS orchestrator-lane execution of organ-owned work.
Recurrence-rate telemetry: proof = the pattern not repeating.

## Ratification vs decision (buttons law, T-260828-0002)

Third context-free-button incident root cause: tasks minted FROM a principal order
re-ask permission they already have (kind=decision auto-renders as ruling
buttons). LAW: principal-origin orders render as "law recorded ✓" (one-line summary,
timestamp, principal quote as source) — NEVER approve/reject buttons. Buttons are
reserved EXCLUSIVELY for genuinely open decisions. Same class: internal
station-to-station bus jargon (e.g. "VERITAS 75% conditional pass noted") must
not reach a principal-visible surface without a plain-words translation layer.

## Naming law (reinforced 2026-08-27)

The QA fleet group is the GLIAL TEAM — never "QAT"/"QATM" (a transcript
artifact the operator wrongly echoed into system records; ledger+bus scrubbed
same day). Any future occurrence in any record = naming defect. General rule:
normalize transcript mishearings at intake via glossary; NEVER propagate a
machine's mishearing into system vocabulary.

## External mirror practice (2026-08-28)

principal deliberately seeds strong external AIs with our architectural digest so
they return independent recommendations ("you aren't big enough to review
yourself yet"). The vOS v14 spec review (T-260828-0147) was one. Standing
process: verify claims vs primary sources; adversarial seat attacks scope
mismatch (server-grade vs macOS launchd) and premature formalism (equations
that decorate rather than compute); opportunities graded adopt/adapt/watch/
reject; FULL CREDIT for what we already own — never re-adopt our own system in
new clothes. External mirrors are the fourth review kind (research/adversarial/
QA/mirror) — they feed the triangle, never replace it.

## B2C privacy wall (placental law, enforced in code)

B2C health data lives in the B2C-walled store ONLY — never the operator agent live, never
public repos, never cross-organism fungal pushes, never shared memory.
Verified structurally in the security review (live probes REFUSED raw
persona→public routing: "two circulations never mix"). Orchestrator-lane
generation of B2C health content = prohibited (same class as wall violation).
No B2C organism = nothing is protected = generate nothing.
