# Roster taxonomy and source correction

## Session lesson
When the user says the roster is too small, do not assume the the operator agent-facing or dashboard-visible roster is complete.

## Durable correction
- Check the broader OpenClaw source of record, including inactive/archived lineage when requested.
- Preserve existing agents; do not recreate them just to satisfy a new categorization request.
- Apply new skillsets, operating roles, and "brains" as overlays on the existing agents.
- Remove cron wrappers, scheduled check-ins, and other operational labels from the real-agent roster unless the canonical source explicitly identifies them as agents.

## Presentation taxonomy that worked
1. Real OpenClaw roster agents
2. Operational systems / engine layers
3. Personal board advisors / coaching-engine personas

## User correction captured
The user explicitly corrected two failure modes:
- "check the inactive roster too"
- "look at the OpenClaw roster, not just the the operator agent roster"
- "don't recreate agents ... take the agents we've already created and add skillsets to them and put them in these roles"

## Reusable takeaway
For future roster corrections, treat headcount disputes as a source-scope problem first, and treat role/brain changes as a taxonomy-overlay problem second.
