# V2 Demo Run — Intake → Awareness → Snapshot → Quick Wins → Upgrade Path

Use this when the user wants to *feel* the V2 layer rather than read a spec.

## Demo shape

1. **Intake**
   - Capture the user’s raw note without rewriting it.
   - Keep exact wording when it matters.

2. **Awareness**
   - Identify the main signals.
   - Separate facts from interpretation.
   - Keep the tone non-diagnostic and plain.

3. **Snapshot**
   - Produce a baseline-preserving summary.
   - State what is stable, what changed, and what is uncertain.

4. **Quick Wins**
   - Give 1–3 immediate next steps.
   - Make them small, concrete, and user-usable.

5. **Upgrade Path**
   - Show what the public layer can do.
   - Point to the premium/moat layer only as an explicit boundary, not as exposed logic.

## Example phrasing

- **Intake:** “You said: …”
- **Awareness:** “The strongest signal is …”
- **Snapshot:** “Baseline preserved: … / New signal: … / Confidence: …”
- **Quick wins:** “Do these now: …”
- **Upgrade path:** “If you want deeper calibration, that lives behind the premium boundary.”

## Boundary audit reminder

When a rename or launch pass is in progress:
- keep the product-line naming only in the intended product surface
- do not leak the new name into fleet-wide docs, ops docs, or archives unless explicitly scoped
- remove duplicate labels in the same pass if the title or heading changed
- verify filenames, headings, and references all agree before handing off

## What this demo is for

- showing the user the public behavior of the release layer
- demonstrating value over the baseline awareness + snapshot stack
- proving the upgrade path exists without exposing private scoring logic
