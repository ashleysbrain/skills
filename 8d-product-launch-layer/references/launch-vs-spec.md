# Launch Skill vs Spec

## What this reference captures
Use this note when the Release layer risks drifting into a product strategy memo.

The Release layer must answer:
- what the public skill does
- what the Vault hides
- what artifact the user can actually receive
- how the baseline is preserved

## Rule learned from this session
When the user asks for the actual skill, the SKILL.md itself is the deliverable.
Do not hand over only a spec, preview, or explanation and call it complete.

The explanatory spec can still exist in `references/`, but the ship-ready file must be the operational skill.

## Verification cue
Before delivery, confirm three things:
1. the file is a real SKILL.md
2. the file describes runtime behavior, not just intent
3. the file is attached or pathable as the actual artifact
