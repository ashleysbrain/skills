# the specialist engine vs AI Health Naming Notes

Session lesson: keep the coaching engine and the AI health engine in separate naming lanes.

## Naming distinction
- **the specialist engine** is the Divinity Science coaching engine.
- A separate **self-healing / maintenance / AI health** operator or engine should not reuse the Wave name.
- If the health engine is AI-first, do not keep the older human-behavior framing in the product name unless the user explicitly wants that legacy umbrella.

## Naming guidance
- Prefer a **class-level 8D name** for the AI health engine, so the lineage is obvious and the system feels distinct from the specialist engine.
- Good pattern: `NAME8D` or `NAME 8D` for the engine, with related subcomponents carrying the same stem.
- For this user, **HEAL** is a strong semantic anchor, but it should be attached to the AI health engine, not the coaching engine.
- Avoid names that blur coach/orchestrator semantics with maintenance/self-healing semantics.

## Useful examples from this session
- `HEAL8D`
- `VITAL8D`
- `Aegis8D`
- `Pulse8D`
- `Sync8D`
- `Nexus8D`

## Pitfall
If the user already has a named coach/product line, do not reuse that token for a different subsystem just because the subsystem also “guides” or “helps.” Distinct function, distinct name.
