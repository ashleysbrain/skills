## Detection Recipe 1: Circularity in Synthetic Benchmarking

### The Pattern

A domain-informed model (physics-informed, biology-informed, etc.) is tested against
synthetic data generated by the SAME domain model it encodes. The informed model
"knows" the generating process, so it appears to outperform an unconstrained baseline.

### How to Detect

1. Read the data generator code and the model code side by side
2. Compare coupling matrices, ODE terms, parameters — are they identical?
3. If the same formulas generate the test data that the model hardcodes → circular

### Worked Example: PIML Prototype Audit (2026-06-13)

**Data generator** (`synthetic_data.py`):
- KAPPA matrix: 8x8 with PSY-PHY coupling = 0.82
- Mean-reversion: `relaxation_rate * (baseline - state)`
- Coupling: `KAPPA[d][dp] * (state[dp] - state[d]) * 0.05`

**Model** (`neural_ode_8d.py` PhysicsInformedODE):
- Same KAPPA matrix (identical values, same ordering)
- Same mean-reversion: `alpha * (baseline - x)`
- Same coupling: `self.kappa[d] * diff * DAMPING`

**Verdict:** The test data was generated by the same physics the model encodes.
Any unconstrained neural network MUST appear worse by comparison.

### What Circular Benchmarking Looks Like in the Metrics

| Metric | Informed | Baseline | Ratio |
|--------|----------|----------|-------|
| Next-day MSE | 10.94 | 11.64 | 1.06x |
| Extrapolation MSE | 19.22 | 81.50 | 4.24x |
| Final-day extrapolation | ~15.9 | ~191.8 | ~12x |

The 6% next-day improvement is the honest result. The "4-12x" comes from
cherry-picking extrapolation metrics where the circular physics advantage
is strongest over long horizons.

## Detection Recipe 2: Cherry-Picked Metric Reporting

### How to Detect

1. Open the results file (`metrics.json` or equivalent)
2. Compute the improvement ratio for EVERY metric
3. Identify which metrics were used to construct the headline range
4. Report the full picture, including metrics where the baseline WINS

### Worked Example: "4-12x Improvement" Claim

The claim appeared in: Strategic Pivot Brief, Marketing Brief, Product Thesis,
Talent Request.

Actual per-dimension results:

| PHY | 16.64 | 19.31 | Physics (1.16x) |
| ENV | 4.48 | 5.03 | Physics (1.12x) |
| SOC | 6.40 | 4.86 | BASELINE (1.32x) |

| FIN | 3.61 | 3.80 | Physics (1.05x) |

The baseline WINS on 4 of 8 dimensions. None of the downstream documents
mention this.

## Detection Recipe 3: Marketing-vs-Code Cross-Reference

### How to Detect

Build a matrix of claimed techniques vs codebase evidence:

| Claimed externally | In architecture docs | In code | Status |
|--------------------|---------------------|---------|--------|
| Langevin SDEs | No | No | INFLATED |
| Landau-Ginzburg | No | No | INFLATED |
| Kramers escape | No | No | INFLATED |
| Wasserstein distance | No | No | INFLATED |
| Riemannian geometry | No | No | INFLATED |
| Sigmoid curves | Yes (psychometric) | No (not in Neural ODE) | PARTIAL |
| Coupling matrix | Yes | Yes | VALIDATED |

Cross-check: if a talent request to BUILD these techniques exists, they are
future work, not existing capabilities.

### Recurring Confirmation (2026-06-13, 17:38 Cycle)

This cross-reference was confirmed again in the marketing sprint documents.
`DIVINITY-SCIENCE-ONE-PAGER.md` line 32 claims "Langevin stochastic equations
for behavior change. Landau-Ginzburg phase transition models" — the same

(`grep -li "langevin|landau.ginzburg"` in non-venv `.py` files) found these
terms ONLY in API docstrings (decorative metadata), never in actual computation
code. The pattern is now systemic across investor-facing, brand-positioning,
and social-media materials. See Check 9 in parent SKILL.md and

## Detection Recipe 4: Validity Checklist for ML Benchmarks

Run this checklist on any ML comparison:

- [ ] Non-circular test data (different generative process or real data)
- [ ] Statistical testing (confidence intervals or p-values)
- [ ] Cross-validation (not a single train/test split)
- [ ] Adequate sample size (power analysis)
- [ ] Multiple random seeds with variance reported
- [ ] Matched model architectures (same capacity)
- [ ] All metrics reported (not just the best)
- [ ] Per-dimension/per-class breakdown
- [ ] Pre-registered comparison protocol
- [ ] No retroactive framing (HARKing check)

## Veto Gate Template

When a fatal finding blocks publication, define these gates:

1. **What specific evidence is missing** (real data, non-circular benchmark, etc.)
2. **Which documents contain the problematic claim** (list all files)
3. **What must change before the veto lifts** (concrete, testable conditions)
4. **Which downstream agents are affected** (search, causal, synthesis, writing)
