# Human-Deliverable Document Pipeline

Any document a person will READ (technical brief, report, explainer, architecture rundown) is generated through the writing-studio document route and specialist organs. The operator dispatches, verifies, and delivers; the operator never authors prose. This skill carries the principal's binding corrections from repeated rejections.

## Hard Rules (each learned from a rejection)

1. **Operator prose is invalid by construction.** If the operator typed the prose (markdown hand-written, pandoc render, hand-rolled CSS), the artifact is wrong regardless of quality — even if you ran real verification on it. The gate is "did a specialist produce it with a custody record," not "is this good." Do not launder hand-made output by attaching checks.
2. **An engine gap is an order, not a shortcut.** When the studio lacks a route or an organ returns canned/degraded content (e.g., a compose endpoint echoing demo content because pydantic silently drops context fields), the correct act is one dispatch: fix the engine defect, build the missing route, generate through it, close with falsification evidence. The gap is the drift's root cause.
3. **Visual QA = inspect RENDERED PAGES as images.** Render pages to pixmaps/screenshots and inspect for misalignment, silently clipped figures, footer drift, overlap, decorative clutter. Iterate full rounds until a fresh pass finds zero defects; log each round. Source-HTML inspection finds none of these.
4. **Paragraph walls are a failure.** Documents humans "nerd out on" need: a decision tree the reader traces, comparison tables, real graphs with sourced axes (schematics explicitly labeled as schematics), callout boxes, takeaway cards per section, and a clickable reference section (every citation resolved to canonical doi.org/arxiv.org URLs, HTTP-200-verified or flagged) plus a curated further-reading block with links and one-line whys.
5. **Generalize internal metrics.** Exact counts of bus messages/runs from different sources read as contradictions to the reader. Describe process and trend direction; the only precise numbers that survive are measured citations from the papers themselves.
6. **Every quality axis the reader cares about needs a panel seat.** A panel without an information-design seat passed an unreadable document unanimously. Add the missing seat with fail-closed authority, then prove it works by re-running the known-rejected artifact through the new panel and confirming it FAILS. A gate that cannot reject the known-bad artifact is decorative.
7. **Science claims never exceed their source.** Fetch the actual papers (doi/arxiv); where the literature is weaker than the text, weaken the text. Uncitable references are removed, not kept shaky. Figures computed from real data list their parameters in the caption; attribution is method-only where only the method is borrowed.
8. **Voice: the SME organism writes.** Documents about the OS are written in the voice of the organism that runs on it (first person, warm but technically precise), including the organism-vs-OS distinction, and open with a factual artifact-backed rundown of what the OS is and what it is working toward (truth-gate posture: no claim without a live artifact, no aspirational stated as shipped).
9. **Show the system getting smarter.** Close with the honest loop: the question arrived → it triggered a real literature scan → it exposed gaps (missing panel seats, missing routes) → the pipeline gained them → the corpus grew → future documents inherit all of it. Name the concrete artifacts that exist because the asker asked. This is the collaborate-and-help-everyone identity, not a delivery transaction.
10. **Scope additions to an in-flight build go by mid-flight session injection** into the live builder session (do-not-restart instruction), not by killing and re-dispatching. Find the live session id from the sibling-agent log (`grep -oE 'ses_[a-zA-Z0-9]+'` on the newest lines), then `sibling-agent run --session <id> "SCOPE ADDITION ..."` — the foreground call may hit the 420s terminal timeout while the injection still lands; verify incorporation via the bus confirmation or the builder's output BEFORE assuming failure and re-sending. Confirm incorporation on the bus.
11. **Reader-facing numbers discipline (principal correction):** never quote exact internal counts (bus messages, tasks, corpus size, service census) in a human-facing document — the reader cannot reconcile them across sources and reads the mismatch as fabrication. Trend/process language only ("growing", "thousands", "an order of magnitude more"); the ONLY exact numbers allowed are values measured and reported by the cited papers themselves.
12. **Ask precisely who the reader is** (name, role, degree, specialty) BEFORE voice and depth are set — a document pitched at the wrong reader (product person vs ML engineer) fails on first contact even with perfect content. A wrong-identity assumption also corrupts memory: write the team roster fact down once, correctly, when corrected.
13. **Personal/measured data enters the deliverable only from a store verified as the subject's own** — identity fields present in the export, or explicit ownership confirmation — re-queried live at build time, with each rendered value sanity-checked against real-world plausibility (a number incompatible with life is a unit bug, not a finding). Demo/test data from any product DB is contamination, not measurement. The subject's testimony ("these aren't my stats") outranks any stored table: halt and audit provenance, never argue from the data.
14. **Clinician-facing data pages are metric cards, not table walls.** Each metric gets latest / trend / range with a one-line explanation of what the score or dimension IS; wide multi-year numeric tables are illegible to providers. State data gaps plainly — an honest "no BP, glucose, or temperature records in this export" earns more trust than a padded table.
15. **Charts in the deliverable are drawn from the real dataset, and the text explains what each chart reflects** — a chart whose caption does not say what the marks ARE (every dot = one seat, center = root) carries no information for a non-specialist reader, and a chart drawn from synthetic/demo geometry is a lie with a professional finish. When paired comparison charts look near-identical, differentiate by labeled verdicts inside each frame, not by implied layout. When chart geometry changes because placeholder data was replaced with real data, say so explicitly: old census, new census, method unchanged.

## Procedure

1. Confirm the asker and audience precisely (name, background, specialty) before generating — wrong-asker assumptions corrupt voice and depth.
1a. Run cheap provenance forensics BEFORE asking the principal to adjudicate data ownership: file size vs real-export expectations, schema shape (flat demo dicts vs vendor API structure with device IDs/timestamps/contributor fields), identity fields, round-value density. A 556-byte two-dict payload with all-round values is demonstrable seed data on inspection — asking the principal "is this yours?" when the file itself answers wastes a round trip and reads as not having looked.
2. Stage the research INPUT with the lab's own engines (search via engine-refined terms, synthesize digest) — engine output is legitimate staging; operator prose is not.
3. Dispatch ONE build order covering: engine fixes needed, route generation, panel (all seats incl. design, judging rendered pages), render, verification (citations vs corpus DB, architecture claims vs live organism), custody record.
4. **Verify the delivered artifact yourself on the file**: page count, clickable links count, key content markers via text extraction, and a grep of the extracted text for unrendered template variables (`{`…`}`) — never report from the builder's summary alone. If the artifact is served at stable URLs in multiple formats, verify EVERY variant at its URL (pdf AND md AND html): a rebuild that swaps only the PDF leaves the rejected markdown live beside it, and the clean PDF hides the stale channel.
5. Deliver with the custody record (organs touched, run IDs, panel verdicts, QA round log) and flag honest gaps.

## Pitfalls

- A compose/creative endpoint returning canned demo content usually means the payload schema silently drops fields (e.g. pydantic models omitting context fields entirely) — reproduce before suspecting the model.
- Hybrid-reasoning models (LLM 5.x) can return `content=""` with text stranded in `reasoning_content` on ANY compose/synthesize path, not just the comment route — dispatch `thinking:{type:disabled}` + adequate max_tokens as part of any engine fix order.
- A paragraph-wall PDF that passes a "unanimous" panel means the panel lacked a seat for the axis that failed — diagnose the MISSING SEAT, not just the document, and prove the new seat works by re-running the known-rejected artifact through it (it must FAIL).
- Re-running the previously-rejected artifact through the new panel is the ONLY acceptable proof a new gate works.
- Bot-blocked publisher DOIs (SSRN/MDPI/Science) are flagged with reasons, never silently dropped or counted as verified.
- Numbers inside figures must reproduce identically across re-computation runs; if they drift, the figure is unstable and must be recomputed.
- A tiny hand-typed JSON "daily" payload with round values (7.2h, 8/10, 60min, 8300 steps) and no API structure is product seed data, not wearable output — real vendor exports carry device IDs, ISO timestamps, and contributor breakdowns (HRV, resting HR, respiratory rate).
- Wearable DB unit traps (Apple Health): SpO2 rows carry unit '%' but STORE a 0–1 fraction (multiply by 100; plausible 82–100%); wrist temperature stores degF (93–99°F). Render units from the value's plausibility, never from a hardcoded label.
- When the deliverable lives in a custody vault the operator is barred from touching, verify through its sanctioned boundary surface (curl the whitelisted URL → pdftotext → grep banned strings + cross-check headline counts) — cross-check numbers against aggregates captured independently of the builder, never against the builder's own pipeline output. The boundary exists so verification never needs filesystem access; a delivered copy cached outside the vault serves the principal.
