# Decision-Routed Three-Division Evaluation

TERMINOLOGY: the three bodies are DIVISIONS (math, art, science), per principal
preference — use "division" in every principal-facing surface; "department" is
legacy wording for the same bodies.

## When to Use
- Evaluating any artifact, deliverable, organ output, review cycle, or
  recurring process — macros and micros both, no exemption by size
- Opening or closing a multi-seat review volley
- Routing inbound information (referrals, papers, links) at intake
- Answering "who reviews this" — never a single default department

## The Model
Three divisions — ART (visual, voice, communication), MATH (scale,
quantity, structure), SCIENCE (claim vs evidence, methodology) — evaluate
EVERY process. Findings ROUTE BY DECISION to the division that owns the
defect class; the owning division owns the fix and the fix re-enters the
review cycle.

UNIVERSAL VISIBILITY: all research and information absorbed by ANY means
(referrals, scans, handoffs, engine reports, principal orders, sensor feeds,
verdicts) is SEEN BY ALL THREE divisions — the dominant division leads the
disposition, but every division receives the read. An intake where any
division did not see the material is an incomplete intake; carry a
three-division visibility record (dominant + both gates named) on every
intake event.

Dominance rotates by need; membership never does. The dominant department
is chosen per artifact by what the output actually needs — never by habit,
recency, or which department shipped last. An all-art board is the same
monoculture defect as an all-one-harness build histogram.

## Procedure
1. **Division read at INTAKE, before any processing**: name ONE dominant
division + the other two as background gates. Record the read with the
row/artifact itself (DB field, ledger note). Intake without a read is
incomplete intake — same defect class as a raw ledger insert.
2. **Seat selection per division lens**: one seat per division lens; pair
   seats across harnesses/lineages so each hunts the other's blind spots
   (claim-vs-number, provenance, portability on one side; new defect classes,
   scale fairness, ornament-as-data on the other). Never all seats from one
   harness.
3. **Route findings by decision, not by sender**: visual/communication
   defects -> art seats; quantitative/scale defects -> math seats;
   claim-vs-evidence defects -> science seats. The finding's class decides,
   not which seat spoke loudest.
4. **Closure = convergence, round-blind**: a volley closes ONLY on zero new
   findings across a FULL rotation of all seats PLUS diff-evidence closure
   of every prior challenge. If a round finds real defects, fix and run
   another round.
5. **Record the verdict trail**: dominant choice, seat list, findings by
   division, closure evidence — attached to the artifact.
6. **Accept a seat's finding by re-deriving it, not by trusting it** — spot
   check the reviewer's math or file evidence before applying the fix (the
   receiving side re-derives; mastermind applies to review handshakes too).
   When two seats disagree on a number, recompute it yourself before
   choosing.
7. **Certify fixes with a same-turn hash, and audit regex edits structurally.**
   Every fix batch must re-hash and re-anchor the artifact in the SAME turn —
   a hash quoted from a pre-edit state certifies nothing and a QA seat will
   (correctly) hold the close. After any regex/replace-based edit, run a
   structural audit (brace/quote balance, `keyframes` block integrity) before
   certifying; a replace that fixes semantics can leave a stray delimiter that
   silently drops the NEXT rule in the file.
8. **Delivered-render QA belongs in the gate.** "Visible at t=0" verified in
   the DOM does not survive the delivery channel. Before sending a rendered
   visual artifact as an image, render it through the delivery path and
   verify ink per section programmatically — see telegram-artifact-delivery
   pitfall 6. A volley that never screenshots the artifact can ship a file
   that is blank on the phone.

## Pitfalls
- **Round counts and clocks are never stop conditions.** A fixed round cap
  ("N rounds then ship") lets the clock decide instead of convergence — the
  classic defect. The stop rule is the convergence condition, nothing else.
- **Never let one division become the default dominant.** Check the
  dominant histogram of recent reads; a monoculture means routing by habit.
- **A clean sweep dispatched before a fix landed cannot close the volley** —
  it reviewed a stale file state. When a fix lands mid-rotation, dispatch a
  micro-confirmation seat scoped to just the delta (the two edited lines),
  and re-hash the artifact so closure certifies the CURRENT bytes.
- **A law stamped but not swept is prose.** When a routing/closure rule
  changes, patch the owning store AND the live surfaces (probes, pools,
  dispatcher tables, every copy of affected scripts) in the same turn —
  stale duplicates regenerate the defect after the canonical copy is fixed.
  (Full correction-adaptation loop: ceo-standing-law-enforcement skill.)
- **In-flight work never pauses for a rule change.** Running seats keep
  running while the system adapts around them.
- **Micros get the lightweight form** (dominant + gates read), macros get
  the full rotation — but no output skips evaluation entirely.
