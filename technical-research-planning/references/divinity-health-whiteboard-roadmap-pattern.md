# Divinity Health whiteboard roadmap pattern

Session-derived notes for turning a science-based health-tech/gamification vision into a board-friendly roadmap.

## Roadmap shape
Use a left-to-right board layout:
1. Science
2. Data
3. Engine
4. Game loop
5. Distribution
6. Revenue
7. Scale

## Build order
- Start with the first user and the first health outcome.
- Define the baseline schema before the game layer.
- Build evidence capture and native scoring before flashy UI.
- Add state interpretation and one recommended next action next.
- Add streaks/quests/rewards only after the state loop is stable.
- Open-core packaging comes after the first loop works, not before.

## Product rules
- Health first, game second, monetization third.
- Gamification should reward consistency, recovery, and agency.
- No shame mechanics, no addiction loops, no coercion.
- The open-source layer must be genuinely useful.
- The premium moat should be obvious: hosted intelligence, personalization, enterprise tooling, or premium assets.

## What to draw on the board
- Use boxes for each layer and arrows for the data flow.
- Under each box, list the 2-4 concrete outputs it must produce.
- Add a bottom metrics row for retention, adherence, outcome change, conversion, referral, and trust.
- Keep the board readable enough that the implementer can translate it directly into files and milestones.

## Common mistake to avoid
Don't start with avatars, social features, or enterprise packaging before the baseline + daily loop prove that the product can change behavior.
