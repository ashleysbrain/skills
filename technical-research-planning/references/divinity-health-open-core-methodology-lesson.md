# Divinity Health Open-Core Methodology Lesson

Session-derived notes for future research/doc work on the Divinity Health / 8D methodology launch.

## Key lessons

- Do not reduce the methodology to a simple 1-10 self-report story if the source model is multi-source and coupled.
- Always separate the **native engine math** from the **display layer**.
  - Native math: database-scored native dimensions, baseline, confidence, deficit/momentum terms, and composite logic.
  - Display layer: 1-10 or 0-100 score for human readability only, after the engine has produced its native output.
- When writing a first-product launch doc, include the open-source boundary inside the product narrative, not as an afterthought.
- For open-core health/AI products, explicitly state:
  - what is open source (methodology core, reference schema, SDK/quickstart)
  - what stays proprietary (predictive models, calibration, couplings, hosted orchestration, enterprise automation)
- For methodology release packs, keep the score-family map explicit instead of collapsing the product into one number. Preserve sub-scores, optional/contextual families, and the worked example.
- If the deliverable is a PDF pitch pack, verify the extracted text after generation.
  - PDFs can render list markers poorly.
  - Prefer deterministic, plain-English line items if the renderer misbehaves.
  - Check for the exact phrases that define the engine contract, not just the visual layout.
- For methodology docs, include at least one worked example with the math spelled out step by step.
- For multi-document launch packs, a reliable default is a combined executive brief plus a technical appendix; only split further when there is a clearly distinct audience or workflow.

## Useful phrasing pattern

- "The user-facing score is a derived output. The scientific layer is the full model underneath it."
- "A 1-10 score is only the display layer; the native engine operates on database-scored evidence, confidence, and composite logic."
- "Open methodology builds trust. Premium intelligence captures value."
- "The master brief or pitch deck should tell the story; the appendix should teach the math."
