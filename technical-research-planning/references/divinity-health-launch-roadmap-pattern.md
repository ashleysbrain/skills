# Divinity Health Launch Roadmap Pattern

Session-derived release pattern for open-core health-product launch docs and board visuals.

## Source-of-truth order
1. Rewrite the *product roadmap markdown* first.
2. Regenerate derived HTML/PDF artifacts from that markdown.
3. Verify the rendered output matches the updated narrative.
4. Only then adjust or resend the visual/whiteboard artifact.

## What must be updated together
- brand split: Divinity Science vs Divinity Health
- wedge: narrow first audience
- flagship: one product first
- open-core boundary: what is open vs hosted
- revenue ladder: free → consumer → API/platform → enterprise → services
- build order: positioning → MVP → beta proof → open-core release → premium expansion

## Verification checklist
- PDF/HTML both reflect the new strategy
- page count is acceptable for the intended format
- extracted text still contains the key category language and open-core boundary
- the visual fits without overflowing its boxes
- if the user asked for an update, the PDF must include the updated content, not just a prettier layout

## Common pitfall
A visually improved whiteboard is not enough if the underlying product document still contains stale positioning.
