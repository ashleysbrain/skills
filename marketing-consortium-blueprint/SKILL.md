# Marketing Consortium Blueprint Skill

## What This Is

A **blueprint** for creating autonomous agent consortiums that drive tasks
through the the operator agent organism's process flows from inception to output. Marketing
is the first use case that proved the pattern. The blueprint generalizes to
ANY domain.

A **consortium** is a task-swarmed collective of specialist agents that forms
around a task, carries it through the organism, and disbands when complete.
Biological isomorphism: **microbial consortium** (different specialists in
symbiotic metabolism of one substrate).

**Naming convention (locked 2026-06-29):**
- Consortium = ephemeral task swarm (forms per idea, disbands on output)
- Consilium = permanent operator brain-suite (boots every session)
- Different lifecycle, different purpose. Never confuse them.

## When to Use

- Building a new autonomous consortium for a domain (marketing, health, legal, etc.)
- Designing the selection math for agent decisions
- Defining the decision sequence (what order formulas run)
- Creating the pathology reporting system
- Wiring the engine /process endpoint contract for sibling-agent
- Generalizing a proven consortium pattern to a new domain

## How to Build a New Consortium (5 Phases)

### Phase 1: RESEARCH (before any building)
1. Gather domain knowledge (elite institutions, named methodologies, case studies)
2. Extract quantitative math (formulas, equations, models)
3. Compile case studies (who did this brilliantly? what were the moves?)

### Phase 2: CURRICULUM (the knowledge layer)
4. Build the domain curriculum (strategic foundations, audience calibration, etc.)
5. Build the selection math (deterministic scoring function + hard gates)

### Phase 3: PROCESS DESIGN
6. Map ALL process flows (not just one — identify every flow type)
7. Build the decision sequence (which formulas run at which phase?)
8. Build the quality gates (domain-specific rules)

### Phase 4: INTEGRATION (connecting to the organism)
9. Build the carriage controller (executable code)
10. Verify all body parts exist and respond (health sweep)
11. File pathology orders for missing parts
12. Wire engine /process endpoints (spec contract for sibling-agent)

### Phase 5: COMPLETION (before ANY testing)
13. Connect everything end-to-end as executable code (no simulated outputs)
14. Verify full integration runs without breaks
15. ONLY THEN test with a real task

**CRITICAL (2026-06-29 correction):** Do NOT push for testing before the
system is fully built. "You haven't even built and connected the engines yet.
You need to build it all the way before that." Build completely, then test.
This is an adiabatic principle: complete each layer before advancing.

## The Selection Math (DNA-Encoded)

```
Score(P, T) = 0.30*DNA(P) + 0.25*EIGHT_D(P) + 0.20*FIT(P,T)
              + 0.15*EVIDENCE(P) + 0.10*CONTRARIAN(P)

Hard Gates:
  EIGHT_D < 0 -> REJECT (harms human wellness, ANY dimension)
  DNA < 0.5 -> REJECT (insufficient brand alignment)

Free Energy Gate (ratio):
  F = COST / [Score * (1 + INFO_GAIN)]
  F >= 1.0 -> SKIP (cost exceeds value)
  F < 1.0 -> ADMIT
```

Weights are domain-adjustable (within +/-0.05 per generation) but the structure
and hard gates are immutable.

## The Decision Sequence (9 Phases)

The formulas do NOT all run at once. They apply at different phases:

| Phase | What Happens | Math Applied |
|-------|-------------|-------------|
| 0. Classify | What is this? Who is it for? | None (classification) |
| 1. Hard Gates | 8D + DNA check | None (rules only — pass or die) |
| 2. Philosophy Selection | Score candidates, hold top 3 | Selection function + free energy gate |
| 3. Audience Calibration | Awareness level, demand state | None (classification) |
| 4. Production | Engines create content | None (creative process) |
| 5. Quality Threshold | Anti-slop + brand + awareness | Rule-based checks |
| 6. Prediction | Will it work? | Bass, K-factor, prospect theory, elasticity |
| 7. Immediate Measurement | CTR, engagement, dwell | Instant metrics |
| 8. Delayed Measurement | Did it work? | A/B stats, ROMI, attribution, incrementality |
| 9. Learning | Get smarter | Bayesian update, parameter refinement |

Key principle: you cannot MEASURE content before it exists. The phase
determines the formula. The agent asks "what phase am I in?" not "which
formula should I use?"

## Pitfalls

- **Never test before building completely.** The system must be fully connected
  end-to-end with real (not simulated) outputs before any test run.
- **Never put project state in the operator agent persistent memory.** Process flows live
  in files, git, and the operator bus. Persistent memory is for durable
  cross-session facts about the user and environment only.
- **Never use heuristics when math exists.** Agent decisions need deterministic
  scoring, not vibes.
- **Never confuse 8D human wellness with system health.** The 8D gate measures
  what content does TO THE HUMAN consumer.
- **Never use anatomical terms as metaphors.** "Spine" = real vertebral column.
  "Birth" = real reproductive process. Process abstractions get process names.
- **Never force a fixed number of categories.** The research surfaces however
  many formula families naturally exist. Do not align to 8 just because there
  are 8 wellness dimensions.
- **Never delete memories to make room.** Memory is a tiered system (T0-T3).
  If T0 (the operator agent buffer) is full, route to T2 (DS O'Keefe), don't destroy T0
  entries. User correction: "You probably just deleted something important,
  and you've done that before."
