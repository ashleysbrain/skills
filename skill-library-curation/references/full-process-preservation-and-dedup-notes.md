# Full Process Preservation and Dedup Notes

## Session lessons

- When the user asks for a process "from start to finish," preserve the full operational flow and all established sub-steps; do not compress it into a simplified version.
- If the user says a process is missing steps, review the whole thread and the current docs together before deciding what to save.
- Treat "stuck" or "not working correctly" reports as a cue to inspect the latest user message against the assistant's last turn for the real workflow mismatch.
- When updating a process skill, make sure related docs stay synchronized across process flow, question flow, state machine, and README-style overview docs.
- If a durable user preference is expressed as a correction, encode it in the governing class-level skill, not only in memory.
- When the workflow has a three-way advisor taxonomy, keep the categories explicit: general coaching advisors, public human-figure mirror advisors, and narrow specialist advisors.
- Narrow specialist advisors should remain highly credentialed and elite within their narrow focus; narrow does not mean low rigor.
- When the user says not to simplify or generalize, treat that as a durable skill-level formatting/workflow constraint for future process docs.
