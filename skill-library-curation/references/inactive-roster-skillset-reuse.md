# Inactive roster + in-place skillset reuse

Session lesson:
- When the user asks to expand or repurpose an agent roster, inspect *active*, *inactive/archived*, and adjacent canonical pools before concluding the roster is small.
- Preserve existing agent lineage when the user says not to recreate agents.
- Prefer adding or reshaping skillsets, credentials, and role assignments on existing agents rather than minting new ones.
- Treat a claim like "we have way more than 72 agents" as a cue to verify the broader roster surface, not just the visible live list.
- For roster redesigns, build a role-by-role credential matrix so each agent's brain/credentials are matched to its operating role instead of using a generic one-size-fits-all profile.
- If the user explicitly asks to review the conversation and update the skill library, make at least one durable curation change when any reusable lesson exists; do not return a no-op pass.
