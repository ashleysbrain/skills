# Skill Library Curation Notes

## Session lessons to preserve

- The user explicitly wants the skill library to be updated actively, not only when a task is obviously broken.
- The preferred shape is **class-level umbrella skills**, not a long list of narrow one-session entries.
- Durable learning belongs in `SKILL.md`; session-specific detail belongs in `references/`.
- When a user corrects style, format, workflow, or legibility, that correction should be embedded into the relevant skill so the next session starts with the improved default.
- If a skill is relevant and already loaded, patch that skill first.
- If multiple skills overlap, note the overlap in the final reply so curation can consolidate later.

## Quick decision guide

- **Patch existing umbrella skill**: if the lesson clearly belongs to an already-loaded or existing class-level skill.
- **Create new umbrella skill**: if no class-level skill cleanly covers the lesson.
- **Add reference file**: if the detail is useful but too session-specific or too verbose for `SKILL.md`.
- **Do nothing**: only when there is genuinely no durable lesson worth saving.

## Examples of durable lessons

- A user prefers concise handoff docs with paste-ready steps.
- A user prefers surgical edits rather than broad rewrites.
- A workflow consistently benefits from a verification step after content generation.
- A recurring bug fix requires a specific ordering of checks or a special tool pattern.
