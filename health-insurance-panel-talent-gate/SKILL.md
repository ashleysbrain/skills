# Health Insurance Panel Talent Gate

Use this when the user wants to brainstorm, design, or operationalize a health-insurance-specific multi-agent panel that must:
- stay aligned with the canonical OpenClaw talent gate
- use elite agent personas with full personality stacks
- adapt personality mode by task
- remain compliant, acquisition-aware, autonomous where appropriate, and AI-native
- preserve a clean separation between the insurance company and any adjacent IP / methodology layer
- explore adjacent ecosystems beyond the obvious medical, dental, and nutrition lanes
- identify one-source / one-front-door experience opportunities even when the backend is hybrid

This is a **spin-off workflow**, not a replacement for the core fleet protocols.

## Primary design rule

**Persona sheet first, then game plan, then dispatch.**

Do not jump directly to implementation. First ensure the panel design is compatible with the current canonical gate, then draft the full persona roster and personality mechanics, then build the project game plan, and only after approval move to active dispatch.

## Mandatory sync rule

Before every run, the workflow must re-check the canonical protocols it depends on:

1. `sibling-agent-talent-gate-protocol`
2. `multi-agent-panel-blueprinting`
3. `business-health-agent-architecture`
4. Any newer talent, persona, or routing protocol the fleet has adopted

### Sync checklist
- Load the latest skill content for the canonical protocols
- Confirm no naming, routing, or personnel rules have changed
- Confirm the panel size still fits the current request
- Confirm the requested domain still belongs in the health-insurance lane
- If the canonical rules have changed, update this workflow before proceeding

### Sync policy
If the canonical protocol version or substance has changed, this spin-off workflow must be revised before it runs. Do **not** continue on stale assumptions.

Session-specific detail lives in `references/session-2026-06-health-insurance-panel-notes.md`.
Market and ecosystem scan prompts live in `references/market-ecosystem-scan.md`.

## When to use
- The user wants a health insurance company concept panel
- The user wants a personae-first talent blueprint before the game plan
- The user wants insurance, compliance, legal, product, AI, and growth specialists in one coordinated panel
- The user wants the panel to be acquisition-oriented and regulator-aware
- The user wants the panel to align with an 8D / reporting / methodology bridge without contaminating the regulated core
- The user wants the agents to have full personality profiles, not just role labels

## Emerging-care and reimbursement expansion

When the user asks to “include the latest science” or to help members access newer care options, expand the panel brief beyond standard medical/pharmacy lanes to explicitly consider:
- peptides and peptide-based care ecosystems
- red light / photobiomodulation therapy and other evidence-based recovery tech
- regenerative medicine and longevity clinics
- wearable-driven recovery and coaching platforms
- other adjacent evidence-based emerging-care services that fit the product thesis

Treat these as *future strategy lanes*, not launch assumptions.

Business-review rule: if the user asks for a review of the company idea itself, pair the panel brief with a separate business review that answers launch wedge, distribution, cost pressure, compliance risk, and competitive positioning. If the evidence is clear, say plainly whether the best launch wedge changed.

When the user asks how members might pay for or be reimbursed for these services, add a separate business-model lane for:
- member reimbursement wallets
- employer-sponsored wellness stipends
- HSA/FSA-compatible pathways where allowed
- preferred-provider discount networks
- cash-pay concierge bundles with partner rebates
- outcomes-based value-share arrangements
- member credits or incentive accounts

Keep the science/adoption question separate from the reimbursement/business-model question so the panel can evaluate both cleanly.

## Scope boundaries

This workflow is for **brainstorming, panel design, and talent-gate prep** only.

It does not:
- draft legal advice as if it were counsel
- make regulatory determinations without specialist review
- design claims or underwriting logic without actuarial input
- merge the insurance entity with the underlying methodology IP

## Panel composition target

Default to **12 agents** unless the user explicitly requests a smaller core.

Recommended balance:
- 5 compliance / risk / legal spine
- 5 product / AI / growth / partnerships / interoperability voices
- 2 optional innovation lanes for reimbursement, wallets, or care navigation

## Canonical persona roster pattern

Each persona should be defined with:
- codename
- role
- elite credential stack
- primary personality
- MBTI
- Enneagram
- Big Five profile
- default decision style
- task-mode variants
- blind spots
- collaboration posture
- validation ownership

### Required personality mechanics
Each persona must have:
1. **Primary personality** — the default operating style
2. **Task-mode variants** — how the persona shifts by assignment
3. **Stress behavior** — what happens under pressure
4. **Challenge style** — how the persona pushes back
5. **Collaboration posture** — how the persona works with the rest of the panel
6. **Elite credential stack** — prestigious university / institution / certification grounding, not vague background labels
7. **Autonomy stance** — whether the persona prefers automation, human gating, or hybrid oversight when the company must run with minimal touch points

## Personality routing rule

The personas must change posture by task:
- strategy / acquisition → principal-strategist mode
- legal / filing → precision counsel mode
- privacy / PHI → hardened guardian mode
- pricing / reserves → conservative quant mode
- claims / fraud → adversarial ops mode
- product → empathetic translator mode
- AI automation → inventive systems-builder mode
- interoperability → standards-first connector mode
- partnerships → alliance-builder mode
- revenue / growth → unit-economics mode
- care navigation → compassionate support mode
- reimbursement / wallet → systems-finance mode

## Workflow steps

### 1. Load the canonical protocols
Read the latest canonical skills before drafting anything.

### 1b. If the user asked for business judgment, not just panel design
Produce a companion business review alongside the panel artifact when the question is about viability, launch sequencing, or market positioning. Keep the review candid and grounded in current market signals.

Support file: `references/health-insurance-business-review-notes.md` contains session-level market signals, launch-wedge conclusions, and source pointers.

### 2. Draft the health-insurance spin-off frame
Establish:
- the insurance company thesis
- the acquisition thesis
- the 8D reporting bridge
- the IP firewall between company and methodology
- any data / reimbursement / wallet ideas that may belong in a separate layer
- the one-source experience goal across member touchpoints
- the autonomous operating model and agent-fleet boundaries

### 3. Create the persona sheet first
Before the game plan, produce a persona sheet for each agent with the full personality stack.

### 4. Build the panel map
Show:
- who owns which hard problem
- who challenges whom
- which personas validate which others
- which personas are allowed to lead in which task modes
- who owns market intelligence and competitive benchmarking
- what ecosystem categories are in scope beyond the obvious healthcare lanes

### 5. Only then create the task game plan
The game plan comes after the personas are approved.

The game plan should explicitly include:
- autonomous AI-native operations with minimum necessary human touch points
- a dedicated market research / competitive benchmarking agent
- ecosystem expansion beyond medical, dental, and nutrition
- a one-source / one-front-door member experience

### 6. If active spawning is requested, go through the talent gate
Use the canonical spawn and dispatch workflow. Do not improvise around it.
