# v2.1 Diagnostic Stack Build Pattern

Reference for the actual code implementation of the Wave Engine v2.1
science-grounded diagnostic stack. Built 2026-07-21. Covers module
structure, the pipeline shape, complexity-gate routing signals, and
the two-layer output model. Use when implementing a similar
science-grounded diagnostic layer on any coaching/advisory engine.

## Module structure

The v2.1 stack lives in its own subpackage, cleanly separated from
the v1 template-based coaching. This is an adiabatic build — it does
not break the existing API.

```
src/wave_coaching/v2/
├── __init__.py              # public API exports
├── framework_registry.py    # tags every component (validated/practitioner)
├── complexity_gate.py       # Fast/Deep path routing
├── motivation_diagnosis.py  # SDT (Deci & Ryan 2000)
├── efficacy_calibration.py  # Bandura (1977)
├── mindset_scoping.py       # Dweck (2006), scoped per Sisk (2018)
├── loss_aversion.py         # Kahneman & Tversky (1979)
├── if_then_planner.py       # Gollwitzer (1999)
├── habit_automaticity.py    # SRHI proxy (Verplanken & Orbell 2003)
├── map_check.py             # Fogg B=MAP (2019)
├── output_model.py          # Two-layer output (Orne 1962)
└── pipeline.py              # Full pipeline integration
```

The v1 pipeline (`classify_situation` + `generate_coaching_guidance`)
remains untouched. The v2 pipeline wraps it:

```python
from wave_coaching.core.coaching import classify_situation, generate_coaching_guidance
from wave_coaching.v2 import run_v2_pipeline

cls = classify_situation(text)
v1_guidance = generate_coaching_guidance(text, cls)
result = run_v2_pipeline(text, cls, history, v1_guidance)
# result has: coaching_response, science_trace, path, complexity_score
```

## Pipeline shape

```
classify_situation() → assess_complexity()
                           ↓
            ┌──── FAST PATH ────┐    ┌──── DEEP PATH ──────────────────┐
            │ everyday_task,    │    │ strategy, advisory, distress,   │
            │ no depth cues,    │    │ depth cues, personal_growth     │
            │ no distress       │    │   ↓                             │
            │   ↓               │    │ motivation_diagnosis (SDT)      │
            │ wrap v1 guidance  │    │ efficacy_calibration (Bandura)  │
            │   ↓               │    │ mindset_scoping (Dweck, scoped) │
            │ output            │    │ loss_aversion_framing (Kahneman)│
            └───────────────────┘    │ habit_automaticity (SRHI proxy) │
                                     │ if_then_planner (Gollwitzer)    │
                                     │ map_check (Fogg B=MAP)          │
                                     │   ↓                             │
                                     │ build_two_layer_output()        │
                                     │   coaching_response (clean)     │
                                     │   science_trace (gated)         │
                                     └─────────────────────────────────┘
```

## Complexity gate routing signals

The gate uses 5 signals, checked in priority order:

1. **Depth cues** (highest priority) — "help me think through", "weigh
   my options", "I'm stuck", "figure out". If present, force Deep Path
   regardless of type or length. Score bumped to >=50.
2. **Distress signals** — "can't stick", "tried before and failed",
   "overwhelmed", "not sure I can". Force Deep Path. Score bumped to
   >=55. These situations need diagnostics MOST — routing them Fast
   would skip the efficacy/motivation diagnosis that addresses the
   actual blocker.
3. **Situation type** — `everyday_task` defaults Fast; `business_strategy`,
   `advisory_panel`, `professional_advice` default Deep.
4. **Text length** — under 50 words biases Fast; over 150 biases Deep.
5. **Domain novelty** — first mention (no history) biases Fast (user
   wants quick orientation on a new topic).

**Calibration pitfall caught in testing:** A personal_growth query
with low-efficacy markers ("I can't stick with anything, I've tried
before and failed") initially routed Fast because the text was short
and had no depth cues. This is exactly wrong — low-efficacy situations
are when the diagnostic stack matters most. The distress-signal check
was added to force these to Deep Path.

## Two-layer output model

Every Deep Path response is split:

- **coaching_response (Layer 1):** clean natural language. The
  `_strip_jargon()` function removes any of these banned terms:
  `map check`, `friction score`, `if-then plan`, `implementation
  intention`, `growth mindset`, `self-efficacy`, `loss aversion`,
  `prospect theory`, `autonomy support`, `intrinsic motivation`,
  `habit automaticity`, `complexity gate`, `cognitive load`.
- **science_trace (Layer 2):** frameworks active, diagnostic results,
  citations. `visible_to_user: false` by default. Exposed when user
  asks "why are you recommending this?"

**Verification pattern:** after building any output, grep the
serialized coaching_response JSON for all banned jargon terms. Zero
hits = clean. This is the demand-characteristics mitigation per Orne
(1962) and McCambridge et al. (2012).

## Framework classification

Every component is registered in `FRAMEWORK_REGISTRY` with:

- `classification`: `validated_science` or `practitioner_framework`
- `primary_citation`: the real paper/book
- `claim_scope`: what the engine claims this component does
- `status`: SETTLED / PROVISIONAL / OPEN

The LLM prompt layer uses this to choose language:
- validated_science: "Research shows..." permitted
- practitioner_framework: "One approach to consider..." only

This prevents Hill/Covey/Seligman from being presented with the same
confidence as SDT/prospect theory/Fogg.

## Diagnostic module pattern

Each diagnostic module follows the same shape:

```python
def diagnose_X(
    text: str,
    classification: Optional[Dict] = None,
    history: Optional[List[Dict]] = None,
) -> Dict[str, Any]:
    # 1. Define language markers for each subtype
    # 2. Count marker hits in user text
    # 3. Pick best subtype (default if no signal)
    # 4. Return dict with:
    #    - the diagnosis (type, level, etc.)
    #    - confidence
    #    - markers detected
    #    - an llm_directive or autonomy_directive for the prompt layer
    #    - citation
    #    - framework_classification
```

The `llm_directive` field is consumed by `pipeline.py`'s
`_build_llm_directives()` and injected into the LLM system prompt.
The LLM follows the directive but never surfaces the jargon in
Layer 1 output.

## Testing pattern

After building, run end-to-end smoke tests:

```python
# Fast Path test — should skip diagnostics
text = "train my dog to sit"
r = run_v2_pipeline(text, {"type": "everyday_task"}, None, None)
assert r["path"] == "fast"
assert len(r["science_trace"]["diagnostics"]) == 0

# Deep Path test — should run all 7 diagnostics
text = "I need a strategy for launching our health AI product. Help me think through the options."
r = run_v2_pipeline(text, {"type": "business_strategy"}, None, None)
assert r["path"] == "deep"
assert len(r["science_trace"]["diagnostics"]) == 7

# Jargon check — Layer 1 must be clean
import json
banned = ["map check", "friction score", "growth mindset", "self-efficacy", ...]
layer1 = json.dumps(r["coaching_response"]).lower()
assert not any(term in layer1 for term in banned)

# Distress routing — low-efficacy text must go Deep
text = "I can't stick with anything. I've tried before and failed."
r = run_v2_pipeline(text, {"type": "personal_growth"}, None, None)
assert r["path"] == "deep"
assert r["science_trace"]["diagnostics"]["efficacy_calibration"]["efficacy_level"] == "low"
```

## Self-audit checklist (run when user says "double check your work")

After building any diagnostic stack, run this 15-point verification.
User's phrase "double check your work" is the trigger. Do not
rubber-stamp — find real bugs.

**Filesystem & compile (5 checks)**
1. All files on disk (`ls -la <dir>`)
2. All modules compile (`python3 -m py_compile <dir>/*.py`)
3. No em dashes in code or docs (`grep -l "—" <files>`)
4. AI-tell scan on all docs (`scan_ai_tells.py <docs>`)
5. Filenames claimed in summaries match filenames on disk (subagents
   sometimes write "ROUND 3" but save as "ROUND3")

**Runtime (5 checks)**
6. End-to-end pipeline runs (v1 -> v2 -> output structure correct)
7. Framework registry counts match architecture doc claims
8. Gate integrity: each gate fires ONLY when it should (PERMA on
   personal_growth only, multi-voice on structured only, etc.)
9. Jargon-leak check: serialize coaching_response to JSON, scan for
   every banned term, zero hits
10. Distress signals force Deep Path (everyday_task + "can't stick"
    must route deep, not fast)

**Science & claims (5 checks)**
11. Every citation traces to a real published work (verify against
    training knowledge; for production, spot-check 3-5 against
    Google Scholar)
12. No actual randomization where adversary excluded it — use AST
    walk, NOT string match (the string "random" appears in comments
    stating "no randomization" and produces false positives)
13. VR exclusion verification: `python3 -c "import ast; ast.walk(ast.parse(source)); ..."`
    looking for `import random`, `from random import`, and
    `random.<attr>` attribute access. String match is insufficient.
14. Doc-to-code consistency: component count in registry matches the
    Round 3 architecture doc's status table exactly
15. Honest disclosure of gaps: no unit tests yet? API not wired in?
    Marker lists English-only? State it. Don't claim completion past
    what was verified.

**AST scan for excluded modules (reusable pattern):**

```python
import os, ast
violations = []
for fname in os.listdir(v2_dir):
    if not fname.endswith(".py"): continue
    with open(os.path.join(v2_dir, fname)) as f:
        tree = ast.parse(f.read())
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            for alias in node.names:
                if alias.name == "random":
                    violations.append(f"{fname}: import random")
        if isinstance(node, ast.ImportFrom) and node.module == "random":
            violations.append(f"{fname}: from random")
        if isinstance(node, ast.Attribute) and hasattr(node.value, "id") and node.value.id == "random":
            violations.append(f"{fname}: random.{node.attr}")
```

**Self-audit honesty rule:** if a check passed for a trivial reason
(e.g., jargon check passes because the v1 guidance is empty in a
test), note it. The check ran, but it did not exercise the real
output. Flag this in the audit report.

## Round 3 OPEN components (intentionally absent)

These 4 components were OPEN after Round 2 and are NOT in the v2.1
build per Popper's mandate (do not build contested components):

- Purpose Lock (Hill) — redundant with existing goal-confirmation?
- Synergy Composition — relabel as Multi-Perspective Composition
- Progress Checkpoints — reground in operant conditioning
- PERMA Scan — gate to personal_growth mode or fold into SDT

They resolve in Round 3. Any that become SETTLED get added; any that
become REMOVED confirm what was already absent.
