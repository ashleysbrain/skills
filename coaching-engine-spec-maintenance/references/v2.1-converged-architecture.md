## v2.1 Branched Pipeline (replaces v2.0 linear 11-step)

```
STEP 0: CLASSIFY SITUATION
  |   Output includes framework_tags, complexity_tier, problem_structure
  v
STEP 1: COMPLEXITY GATE
  |   assess_complexity() -> "fast" or "deep"
  |
  +---> FAST PATH (simple tasks, everyday_task, short input)
  |       classify -> gate -> generate (template) -> output
  |
  +---> DEEP PATH (complex tasks, strategy, growth, multi-step)
          classify -> gate ->
          motivation_diagnosis -> efficacy_calibration ->
          mindset_scoping -> multi_perspective_composition ->
          coaching_generation (two-layer) -> map_check ->
          habit_automaticity -> if_then_plan -> progress_checkpoints
```

PERMA Scan is conditional: triggers only when situation is personal_growth
AND complexity is deep AND well-being signals are present.

## What Changed from v2.0 and Why

### Purpose Lock (Hill) — REMOVED

Redundant with the existing goal-confirmation question ("What outcome do you
want here?"). Locke and Latham (2002) show goal specificity is the active
mechanism; the engine's clarifying-question layer already operationalizes it.
Hill's framework adds no second validated mechanism. Even as an optional
practitioner layer, it occupied architectural space for zero marginal function.

Falsification: if an A/B test using Klein et al. (2001) goal-commitment scale
showed Hill's definiteness-of-purpose language produced measurably higher
commitment than a plain goal question, removal would be refuted.

### Synergy Composition — RELABELLED to Multi-Perspective Composition

Covey (1989) dropped from citations (no falsifiable mechanism). Page (2007)
retained. Now tagged `practitioner_framework` because applying Page's theorem
to LLM panel composition is untested.

Key addition: `problem_structure` field. Multi-voice panel triggers only for
structured problems (decomposable into distinct analysis dimensions like
"Should I take this job?" -> compensation, growth, lifestyle, risk).
Unstructured problems ("I feel lost") use single-voice regardless of
complexity tier.

Falsification: post-interaction quality rating (1-5) comparing multi-voice
vs. single-voice for structured problems.

### Dopamine Milestones — Progress Checkpoints (FR schedule)

Two changes: (1) renamed from Dopamine Milestones to remove speculative
neuroscience metaphor, (2) grounded in operant conditioning literature.

Variable-ratio (VR) schedules produce the highest response rates per Ferster
and Skinner (1957), but VR's mechanism is the same one driving slot-machine
engagement (Schull, 2012, *Addiction by Design*). Applying VR to voluntary
coaching without disclosure creates an ethical problem. With disclosure it
is transparent but awkward and trust-reducing.

Fixed-ratio (FR) is the default: every completed milestone receives
process-based acknowledgment. Grounded in Nevin (1988) behavioral momentum
(consistent reinforcement builds resistance to disruption). Integrates with
Growth-Mindset Language Layer (process praise for every milestone).

Falsification: if ethically-disclosed A/B testing showed VR produced >15%
higher adherence without reducing trust scores, VR could be considered.

### Friction Score — REPLACED with Habit Automaticity Assessment

The original 1-5 Friction Score had no validated measurement instrument.
Replaced by SRHI-derived assessment (Verplanken and Orbell, 2003) using
three subscales: contextual cue stability, behavioral frequency, perceived
effort. Outputs a structured assessment, not a bare integer.

Status: PROVISIONAL because the text-signal proxy adaptation is novel and
needs calibration against administered SRHI scores.

### PERMA Scan — GATED to personal_growth mode

PERMA has partial overlap with SDT:
- Engagement <-> Competence
- Relationships <-> Relatedness
- Positive Emotion <-> Autonomy (partial)
- Meaning — NO SDT equivalent
- Accomplishment — NO SDT equivalent

Folding into SDT would lose Meaning and Accomplishment. These are relevant
for life-orientation goals but add unnecessary load for everyday coaching.
PERMA triggers only when all three conditions are met: personal_growth
classification, deep complexity, well-being/meaning/flourishing signals.

### Mindset Layer — SCOPED to language effects

Claims language-level effects only (process praise, strategy naming).
Population-aware: `population_context` field adjusts intensity based on
whether the user signals high-risk learner (larger effects per Sisk et al.,
2018) or general context (smaller effects). Outcome claims restricted to
high-risk contexts per Yeager et al. (2019).

### Two-Layer Output Model — NEW

Separates coaching language from science labels. coaching_response contains
steps, questions, next actions in plain language. science_trace contains
framework tags, diagnostics, citations. science_trace.visible_to_user
defaults to false, surfaced only when user asks "why this approach?"

Addresses demand-characteristics risk (Orne, 1962; McCambridge et al., 2012).
LLM system prompt explicitly forbids jargon terms in coaching_response.

## Implementation Spec Details

### FRAMEWORK_REGISTRY

Each component has a registry entry:
```python
{
    "component": "motivation_diagnosis",
    "classification": "validated_science",
    "primary_citation": "Deci & Ryan 2000",
    "claim_scope": "motivation type classification"
}
```

For `practitioner_framework` components, LLM prompt uses "one approach to
consider" language instead of "research shows."

### classify_situation() output gains:
- `framework_tags`: list of active frameworks and their classification
- `complexity_tier`: "fast" or "deep"
- `problem_structure`: "structured" or "unstructured"

### assess_complexity() signals:
- situation type (everyday_task biases fast)
- text length (<50 words biases fast)
- domain novelty (first mention biases fast)
- depth cues ("help me think through this" biases deep)
- conversation history depth (first interaction biases fast)
- user can override ("give me the deep analysis")

### scope_mindset_language() output:
- language_mode: process_praise | strategy_naming | growth_framing
- population_context: high_risk | general
- outcome_claim_level: language_only | outcome_suggested
- intensity: low | moderate | high

### assess_habit_automaticity() output:
- contextual_cue_stability: low | moderate | high
- behavioral_frequency: novel | occasional | recurring
- perceived_effort: low | moderate | high
- automaticity_level: novel | developing | established
- friction_reduction_target: <weakest subscale>
- recommended_micro_step: <tiny next action>

### generate_coaching_guidance() output:
```python
{
    "coaching_response": {
        "greeting": "...",
        "understanding": "...",
        "steps": [...],
        "clarifying_questions": [...],
        "next_action": "..."
    },
    "science_trace": {
        "frameworks_active": [...],
        "diagnostics": {...},
        "citations": [...],
        "visible_to_user": false
    }
}
```
