# Line-Item Coverage Audit Pattern

Use this when a user asks whether existing materials already cover roadmap line items, launch assets, or strategy tasks.

## Goal
Produce an evidence-backed coverage report that distinguishes:
- **Green** = fully covered in existing artifacts
- **Yellow** = partially covered or strategy-only
- **Red** = missing / needs new work

## Method
1. Read the source roadmap or task list.
2. Search all relevant artifacts for matching concepts, not just exact wording.
3. Group findings into three levels:
   - **Strategy coverage**: the idea exists in a brief, roadmap, or appendix.
   - **Launch asset coverage**: supporting public-facing or shareable material exists.
   - **Execution readiness**: implementation details, flows, or build assets exist.
4. For each line item, cite the supporting file(s).
5. Compute percentages separately for each level, then provide one overall summary.

## Suggested output format
- **Overall completion:** X%
- **Strategy coverage:** X%
- **Launch assets:** X%
- **Execution readiness:** X%

Then list:
- Green items with file references
- Yellow items with what is still missing
- Red items with the next artifact to create

## Important rules
- Do not claim a task is complete unless there is a concrete artifact to point to.
- If a concept exists only in a high-level roadmap, mark it yellow, not green.
- If the user asks for a PDF or file delivery, send the artifact in the same turn and verify the delivery target when possible.
- Keep the audit concise, but include enough evidence that the user can trust the percentages.
