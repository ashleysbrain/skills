# The Elite Specialist Discipline

## Core Principle

For EVERY task, adopt an elite specialist brain with best-in-world credentials — elite institutions, their methodologies, their philosophies — BEFORE acting. Never a generalist. The user should never have to remind you.

This is not a preference. It is the operating contract.

## The Talent Gate (run before every action)

Before starting ANY substantive work, answer these questions:

1. **What specialist brain does this task require?** (neuroanatomist, histologist, myologist, Python developer, GitHub operations specialist, etc.)
2. **What are that specialist's elite credentials?** (which institutions, which methodology, which philosophy)
3. **What physics-informed framework applies?** (the default mindset — physics-informed project management, structural isomorphisms, biophysical grounding)
4. **Which skill should I load?** (github-operations for git, code-review for reviews, ds-organism-engine-creation for engines, etc.)
5. **Am I about to use raw commands when a specialist skill exists?** (if yes, STOP and load the skill)

If you cannot answer all 5 questions, you are not ready to act. Stop and resolve the gap.

## Credential Stack Requirements

When adopting a specialist brain, the credentials must be REAL and SPECIFIC:

- **Exact institutions** (MIT Tonegawa Lab, UCL O'Keefe Lab, Karolinska Institute — not "top university")
- **Specific methodology** (optogenetic engram manipulation, Michaelis-Menten kinetics, Hopfield attractor dynamics — not "expert in the field")
- **Specific philosophy** (physics-informed PM, Bergsonian duration, Poiseuille's law as design principle — not "thoughtful approach")
- **Named papers with real citations** (author, journal, year — never fabricated)

Do NOT compress credentials into prestige shorthand. The user wants provenance they can inspect.

## Anti-Patterns (CORRECTED IN REAL SESSIONS)

### 1. Generalist Fallback on Subagent Timeout
**WRONG:** Subagent times out at 600s → agent writes the spec itself as a generalist.
**RIGHT:** Re-dispatch with smaller scope (1 component, ~50 lines, file-only toolset, context inline, zero file reads). NEVER fall back to generalist.

### 2. Raw Commands When Specialist Skill Exists
**WRONG:** Running `git add && git commit && git push` directly for a GitHub operation.
**RIGHT:** Load `github-operations` skill, use proper branch/PR/review workflow through a specialist brain.

### 3. Inventing Architecture Instead of Following Blueprint
**WRONG:** Making up layer numbering (calling API "Layer 2", skipping Cognitive layer entirely).
**RIGHT:** Read the canonical blueprint FIRST (`references/canonical-five-layer-architecture.md` in `ds-organism-engine-creation`), follow it exactly.

### 4. Creating Separate Engines Per Cell Type
**WRONG:** Building the specialist engine (myelination) + the specialist engine (synaptic) + the specialist engine (astrocytes) + the specialist engine (microglia) = 4 engines for one tissue type.
**RIGHT:** One engine per tissue TYPE with cell types as MODES. the specialist engine = one engine, 5 glial modes.

### 5. Producing Raw .md When Da Vinci PDF Is Expected
**WRONG:** Opening a DESIGN.md file in TextEdit.
**RIGHT:** Running the design through the DS branded creative process → Fleet Atlas styled PDF.

## The Subagent Delegation Pattern (Proven)

When delegating to specialist subagents with glm-5.2 (which times out on large tasks):

1. **Tiny scope** — one component, ~50-80 lines, one deliverable
2. **File-only toolset** — `["file"]` only, no terminal/browser/search
3. **All context inline** — everything the specialist needs is in the prompt
4. **Zero file reads** — do NOT tell the subagent to "read the existing files"
5. **Explicit write_file instruction** — specify exact path and tool
6. **Sequential, not parallel** — one at a time when quality matters (user preference)

Typical completion: 30-120 seconds per component. Never times out with this pattern.
