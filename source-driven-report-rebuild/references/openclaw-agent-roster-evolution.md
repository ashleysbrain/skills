# OpenClaw agent roster evolution note

## Durable lesson
When a user asks for an expanded agent dossier, roster matrix, or persona/credential refresh:
- inspect the *full* OpenClaw roster, not only the the operator agent-facing roster
- include inactive, archived, and potential-revision agents when the user asks for "all agents" or says the fleet is larger than the visible roster
- preserve lineage: revise existing agents with added skills, credentials, personality variants, and operating roles instead of recreating new agents by default
- separate current roster, inactive roster, and recommended-evolution candidates so the user can see what already exists versus what is being proposed
- if the source set is incomplete, call that out explicitly rather than silently narrowing scope

## Output pattern
Best practice for dossier rebuilds:
- full roster inventory
- recommended revised persona for existing agents
- elite credential stack
- skillset expansion profile
- operating note that explains the role change or placement decision

## Verification
- confirm the source inventory includes active + inactive where available
- confirm the final artifact clearly labels current vs proposed roles
- confirm no existing agent was accidentally duplicated as a new identity unless the user requested recreation
