# Qubit TWC layout lessons (session-specific)

Use this as a quick regression checklist when rebuilding the 8D Qubit AI Agent TWC/algorithm document family.

## User corrections from this session
- Do **not** use 1–10 mapping language in Qubit scorecard/product docs.
- If the user asks for a specific subset of algorithms, keep the deck scoped to that subset.
- For this rebuild, the user wanted the ADHD executive-function nutrition layer included.
- Separate ADHD and nutrition into distinct subcategories under the most important proprietary TWC layer instead of blending them together.
- Do **not** include sexual health / kink / Eros / Kinsey content unless explicitly requested.
- Keep the presentation pattern consistent and readable, especially for dense technical decks.
- When the doc includes multiple calculation families, separate the equations into distinct subsections/cards immediately after the core metric rather than grouping them into one block.
- Add an explicit status indicator to each calculation card when the user asks whether the calculation is live or still in development.
- If a section label is hard to read, fix contrast/color in the rendered artifact before delivery.
- If two related documents can be merged without losing clarity, prefer one combined source-driven artifact with a clear status map.
- Preserve all user-approved source content during a merge; do not delete material just to simplify the layout.
- If a source model treats time/place/other 5WH fields as sequences, paths, or multi-point intervals, encode that directly instead of flattening them to single scalars.
- When the source mixes scientific formulas with custom scoring logic, label which parts are standard science/physics and which are proprietary/product-defined.
- For publication-minded decks, make the provenance label visible on every equation/card so the team can quickly separate literature-backed equations from original scoring transforms.
- If the user asks for a support family to appear immediately after the core metric, treat that order as part of the content requirements, not just a layout preference.

## Practical implications
- Before finalizing, search the source doc for forbidden mapping language and scope drift.
- Verify the HTML and PDF render after edits.
- If the request is about "the last doc", assume the most recent artifact in the series, then confirm its content matches the user’s stated scope.
- Status labels should be explicit and consistent across the deck (for example LIVE, DEV, SPEC, RESEARCH), with the label visible at the top of each calculation card.
- For technical audiences, add a short layer/architecture explanation so they can see how the algorithms connect to the open-core stack.
