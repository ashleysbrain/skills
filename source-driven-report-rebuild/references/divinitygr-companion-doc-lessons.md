# DivinityGR companion-doc lessons

Session-derived notes for paired algorithm + gamification PDF work.

## What worked
- Build the companion as a sibling artifact, not an embedded appendix.
- Add visible, clickable links in both directions:
  - main algorithm PDF → companion PDF and HTML source
  - companion PDF → main algorithm PDF and HTML source
- Put the link chips near the top where the team will actually notice them.
- Rebuild both PDFs after the HTML edits and verify the rendered artifacts, not just the source.

## What the user wanted more of
- Every layer/algorithm card should show:
  - status: LIVE / SPEC / DEV / RESEARCH
  - provenance: standard science vs Divinity Science product logic
- Gamification layers should explicitly separate:
  - goal
  - quest
  - XP
- Quest names should sound human and operational, not AI-generated or abstract.
- Example names that felt better were plain-language, action-oriented, and tied to real-life moments.

## Human-friendly quest naming pattern
Prefer labels like:
- Get the morning back on track
- Reset after a rough patch
- Pull the day back together
- Make it fit real life

Avoid labels that sound like internal schema names, generic AI phrasing, or overly technical abstractions.

## Verification checklist
- PDF exists and has nonzero size
- Clickable links are present in the rendered PDF
- Link destinations appear in the other document too
- Status/provenance notes are visible in the rendered output
- Quest examples read like something a team could present to humans
