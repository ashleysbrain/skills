# Combined master PDF editing lesson

## Session takeaway
When a user wants a team-ready technical PDF, the final artifact should read like a release document, not a work log.

## Keep in the deliverable
- The actual algorithm/content sections
- A concise opening legend for status and provenance
- Per-section or per-card status labels when multiple algorithms are present
- Layering or connection notes that explain how the algorithms stack together
- Separate sections for conceptually distinct families, such as goals vs quests vs XP
- Explicit notes when inputs are multi-point rather than single scalar fields, especially for 5WH-style frameworks

## Remove from the deliverable
- Meta commentary about what was changed
- Explanations aimed at the editor rather than the team audience
- Duplicate front-matter that repeats the same status/provenance key in multiple places

## Readability checks
- Status chips and section headers must be high-contrast and readable in the rendered PDF
- If a section label is hard to read, fix the rendered contrast before delivery
- Verify the exact final PDF that will be handed to the user

## Combination pattern
- Merge related documents into one master PDF when the user asks for a single presentation artifact
- Keep companion explanations only if they serve the team audience directly
- If the user wants a combined document, prioritize one coherent structure over two loosely related PDFs
