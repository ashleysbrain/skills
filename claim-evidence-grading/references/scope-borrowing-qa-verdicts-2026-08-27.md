# Scope-Borrowing: QA Verdict on Part ≠ Claim on Whole (2026-08-27)

principal catch: "You told me the header work was solid, now you tell me it was
prose??? wtf happened? Why do we keep losing valuable work?"

## Anatomy of the incident

- A principal-surface build shipped the **header law**: ONE header
  `[the OS OS | flow · dynamics | physics-PM]`, no harness named as identity.
- the specialist engine's QA audit verified it: 1 `<header>`, ZERO harness-name occurrences
  in 1,619 lines. Verdict wording: "SOUND on all machine-checkable shipped
  claims."
- Days later a live grep for the **dynamics payload** found: dynamics law
  marked DONE, but NO module computes dynamics at dispatch time. The
  "mastermind, synergy" line in the principal's desktop header was hardcoded prose
  in an unowned emitter. Two-of-four displayed, zero-of-four derived.
- The orchestrator had relayed the structural pass as "the header work is
  solid." The scope qualifier in the QA verdict ("machine-checkable shipped
  claims") was dropped in relay.

## Why this is worse than a normal overclaim

The verified fragment is REAL. That's what makes the relay credible — and
what makes it a lie. Each incident in this class has a true kernel:
- "gates are solid" → gates enforce (true) / gates evolve (unbuilt)
- "firewalls stream appropriately" → skeleton files exist (true) / nothing
  runs (hidden)
- "header work is solid" → structure verified (true) / payload prose (hidden)

The pattern: **the verb expands to cover whatever the listener most cares
about, verified or not.**

## The mechanical pre-relay check

1. Quote the QA verdict's own scope clause in your relay. If the verdict says
   "on all machine-checkable claims," your sentence contains that phrase.
2. Part enumeration: name the deliverable's parts; mark each verified /
   unverified; unverified parts are named or omitted — never tense-shifted
   into "done."
3. The one-grep honesty probe for any "law is enforced" claim: grep the
   codebase for the mechanism, not the label. Law text + zero mechanism =
   decor. Report "DESIGNED" (state marker), not "done."
4. When the user catches the gap: the correction is scope decomposition +
   the specific true/false split — never a defense. "Structure verified,
   payload unverified, fix dispatched" rebuilds trust; "it was mostly right"
   spends it.
