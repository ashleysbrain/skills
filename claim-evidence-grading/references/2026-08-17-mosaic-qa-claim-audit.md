# Claims-as-Code Mechanical Audit (2026-08-17 the OS QA pass)

Trigger: principal directive — "do another thorough QA pass on your work; find the gaps
and things you claimed you did but did not do." The session's registry deep-dive
had been reported complete in a confident summary. 10 of 40 claims were false or
incomplete as worded.

## The method (7 steps, all mechanical)

1. **Freeze the claim list first.** Extract every checkable assertion from your
   own prior reports into a list BEFORE touching anything. This session: 40
   claims (fleet=81, zero collisions, 25/25 persona codes, validator exit 0,
   edits committed, gates green, no scratch files...).
2. **Write a read-only audit script — claims as code.** Each claim becomes
   `grade(claim, bool, evidence)` backed by a mechanical probe: import + len,
   Counter for duplicates, yaml parse + set equality against the live source,
   subprocess selftest, `git status` grep, symlink existence, bus row sanity.
   NO fixes inside the audit pass. Audit first, fix after.
3. **Run once, expect C grades.** This pass: 30 A / 10 C.
4. **Classify each C: real defect vs audit-probe bug.** One probe was itself
   broken (brittle exact-string grep spanning a backtick; the target patch had
   landed fine). Fix the probe separately from the target — never grade the
   target down for a broken probe, never pass it on a broken probe either.
5. **Fix in a separate script, each fix verified by read-back** (re-read the
   artifact, re-run the probe that failed).
6. **Archive the audit script as a claim ledger**
   (`audit/claim-audit-YYYY-MM-DD.py`) — a re-runnable proof, not a prose
   assertion of quality.
7. **Re-run the FULL audit + full test battery fresh** and report residual C's
   with their classification honestly (this re-run had 2 residual C's, both
   audit-tool noise: pycache regenerated by the audit run itself, and the
   brittle probe).

## What the in-session "done" reports had missed (all caught mechanically)

- 6 persona ECS codes were fleet-phantoms: the join filled only None entries;
   existing codes were never re-validated after the fleet reclassified
   04.07→04.09. Containment check caught it instantly.
- 4 live-bus defects in the synergy gate that its 5/5 synthetic selftest
   missed (self-block, operator-name tokens as overlap, no reading age decay,
   own done work listed back). See tool-output-verification-discipline #19.
- Registry edits uncommitted in agent-organism; entire the OS package had no git.
- Derived artifacts (ORGANS.json/STATUS.json) stale: old version, wrong store
   count, missing surface fields — written before a later source change.

## Rules distilled

- A claim graded against a narrow probe is graded against nothing — probe the
  live artifact, not the code that wrote it.
- Derived artifacts (status/manifest/registers) drift the moment their source
  changes; audits compare derived-vs-source, never derived-vs-memory.
- Every "fixed" claim needs read-back plus a fresh re-run of the original
  failing probe; and the fix script must be separate from the audit script so
  the ledger stays honest.
- Self-reported summaries are the input to this audit, never its substitute.
