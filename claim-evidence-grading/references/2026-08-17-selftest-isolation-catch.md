# 2026-08-17 — Selftest Self-Generated Evidence (scheduler organ, QA-PASS-10)

## The claim under audit
Pass 9 reported: "scheduler_queue organ 9/9 selftest live" — genuine PASS output, exit 0, produced twice. Pass 10 re-verified it mechanically.

## What re-verification found
`selftest()` opened with `DB.unlink(missing_ok=True)` where `DB = PKG / "stores" / "scheduler.db"` — the PRODUCTION store. The selftest:

1. Wiped the production queue (any real enqueued work would have been destroyed).
2. Wrote 11 fixture rows into it (`high-value`, `urgent`, `race-task` claimed by `r1`, ...).
3. Ran its assertions against that polluted production store.
4. Left the residue behind, so `store_health` later reported the store **UP-fed** — a lying liveness probe: schema alive, zero real work, "fed" reading generated by test residue.

Every number in the 9/9 was genuine tool output; both claims it supported (organ verified, store fed) were false. Same family as crontab-theater: schedule is not function; a pass is not verification when the test manufactures its own evidence.

## The fix chain (three defects, each exposed by fixing the previous)
1. **Temp isolation.** `selftest()` rebinds `DB` to a `tempfile.mkdtemp()` fixture and restores it in `finally`; production store purged of residue (11 rows, then VACUUM). Exposed defect 2.
2. **macOS spawn re-import.** The atomic-claim test spawns racer processes via multiprocessing. macOS default start method is spawn — children re-import the module fresh, so the parent's `global DB` rebind is invisible to them; racers silently ran against production (empty) instead of the fixture, and the race test failed. Fix: `connect(db_path=None)` accepts an explicit path; racers receive `str(DB)` as a process arg. Rule: never rely on module-global rebinding across process boundaries on spawn-method platforms.
3. **Fixture residue at source.** T2 called `complete(old)` on a task that was never claimed. `complete()` only transitions claimed→done, so the call was a silent no-op and the row (plus `urgent`) stayed queued, polluting T4's fixtures. The earlier "fix" drained the residue inside T4 (downstream) — masking, not fixing. Correct fix: each test drains its own residue before the next test starts. Also: assert on `complete()`'s bool return, or the fixture lies downstream.

Verification after the fix: 9/9 across three consecutive runs; production store 0 rows before AND after each run. The before/after row-count is the proof of isolation — the pass line alone is not.

## Probe rules this adds
- "Organ tested N/N" claims: confirm the selftest is isolated; row-count the production store before and after the battery.
- Liveness "fed" readings are unreliable on any store a selftest can write to; residue reads as fed. A store containing only test rows is UP-empty.
- State-transition APIs that return bool (claimed→done): a False return means no-op; unchecked no-ops leak fixture state into later assertions.

## Related: island-audit probe set (same pass, architecture lens)
The companion whole-OS scan that finds organs that are built but unwired:
- **Producers/consumers**: `grep -rln "<module-import>" <fleet roots>` excluding the module itself — zero external hits = island (the scheduler had zero producers and zero consumers fleet-wide).
- **Registry health**: `Counter` over entry `status` — 26/27 unprobed means `select()` ranks nothing (measured-facts-only routing over an empty fact base).
- **Event fanout**: count subscriber code reading the event log; 2 events logged + 0 subscribers = dead fanout despite a spec.
- **Store manifests**: every store file needs a matching `*.store.json` manifest or it is invisible to access control and liveness (scheduler.db had none; fixed by writing the manifest).
