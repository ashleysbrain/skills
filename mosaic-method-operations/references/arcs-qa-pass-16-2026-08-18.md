## 1. Strategic arcs layer (trigger: principal "too narrow" correction)

**Signal (verbatim):** "These work streams aren't thinking long term,
right? This is very narrow…" — five workstreams (WS-1..5) were the
whole visible universe with nothing above them. Campaigns ≠ strategy.

**Built:** `stores/arcs.json` (5 arcs, each with horizon, MEASURED
north-star metric, serves[] → WS ids, why, review cadence) +
`gates/arcs_view.py` (renders ARC → WS → top tasks from live stores).

- ARC-1 PROVE THE METHOD (6-12mo): 30 days autonomous gap→build→close
  with zero human relays + one methodology writeup to a real venue.
- ARC-2 SHIP THE OS (6-12mo): first organism on foreign hardware, a
  non-the principal user completes 10 conductor tasks.
- ARC-3 THE MODEL ECONOMY (12mo+): 60%+ microtasks routed by measured
  capability at sub-cent cost + one Hebb specialist passing rubric.
- ARC-4 ORGANISMS AT SCALE (12mo+): 5 organisms on signed fungal
  updates 30 days, local score ownership, consent-gated upstream.
- ARC-5 SCIENTIFIC AUTHORITY (9-18mo): sustained 2+ pubs/month with
  credibility-weighted points.

**Design rules learned:**
- Every north-star must be COUNTABLE (days/users/%/counts), never
  assertable. Measurability check: grep the metric text for countable
  terms — a metric needing interpretation is a bug.
- Every workstream must be served by ≥1 arc (orphan check) and no arc
  may serve a nonexistent WS — QA'd via set comparison of arcs.serves
  vs DISTINCT workstream in ledger.
- Count discrepancies between views: check whether a live minter
  (gap_hunter) fired between renders BEFORE suspecting data
  corruption. RES 15→23 was fresh autonomous mints, not a bug.

**Gotcha:** write_file to a NEW file under stores/ can trip the
baseline-first gate ("this turn looks like an edit to an existing
artifact") — create via python file-op in terminal instead.

  mints. Re-ran sweep to 0. LESSON: backfills of a shared DB are never
  one-shot; repeat the null-sweep until 0 and expect recurrence.

  INSERT), T-0102 closed with empty outcome. Rubric judge scored both

  stage="rubric:X.XXX/VERDICT" UPDATE. NOTE: rubric_judge API is
  `score(task_id)` (str), NOT `judge(c, tid)` — no connection arg.

  prefix/workstream auto-match verified.

Macro:
- Arc ↔ WS consistency: orphans none, phantom serves none, unique ids.
- Volley tick carried 3 wiring defects found by READING the script:

  step logs nothing).

  For every "engine exists" claim, grep the runner (tick/cron/launchd)
  for the invocation.
