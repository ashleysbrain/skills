## Defect class: stale-process cache poisoning

The firewall passed its battery and the served surface was verified
clean — and 25 minutes later the blocked content was BACK. Root cause:

- Long-running API server (launchd, port 8310) imported the engine
  module at process start, BEFORE the firewall patch.
- At cache TTL expiry (30 min), that stale process regenerated
  tech_pulse_cache.json WITHOUT the firewall, overwriting the clean
  cache written by the patched direct run.
- Even after `launchctl kickstart -k` restarted the server onto the
  new code, it happily served the poisoned cache (TTL not expired).

**Lesson (binding)**: verifying an engine fix requires verifying the
PROCESS that serves it, not just the code + one clean run. Sequence:
1. Restart every long-running process that imports the changed module.
2. Force-regen every on-disk cache THROUGH the live route
   (`?force=true`), not just a direct function call.
3. Only then probe the served surface.
A "0 leaks" claim is true only at the moment of measurement unless the
regeneration path itself is firewalled.

## Firewall falsification battery shape

Three batteries, each falsifying a different failure mode:
1. **False positives** — legitimate wellness content (sleep, CGM, HRV,
   exercise, meditation) MUST survive the blocklist. 10/10 PASS.
2. **Bypass** — case variants (CIALIS), punctuation (Cialis™), URL
   slugs (npr.org/...cialis-viagra) must be caught. Check title AND
   URL — URL-only vectors are invisible to title-regex.
3. **Honest misses documented, not hidden** — hyphen-dissolved
   (c-i-a-l-i-s), typo variants, spaced letters, soft phrasing ("ED
   pills") pass through. Accepted deliberately: those shapes don't
   occur in HN-sourced titles and tightening further eats legitimate
   wellness content. Recorded as known gap.

Blocklist design rule: block BRAND CLASSES (ED drugs, GLP-1 brands,
TRT clinics, D2C telehealth cos), not single product names — the principal
objection was class-level ("not aligned with the 8Ds of wellness
concept"), so the membrane is class-level. Include an honest `blocked`
ledger in the payload so refusals are auditable.

## Environment pitfalls (verified workarounds)

- **Playwright + PYTHONPATH leak**: PYTHONPATH pointed at the
  hermes-agent 3.11 venv, so python3.13 imported the 3.11 playwright
  and died on `greenlet._greenlet` (C-extension mismatch). FIX:
  `env -u PYTHONPATH <venv>/bin/python3 script.py` — run the venv's
  own interpreter with PYTHONPATH stripped.
- **Baseline-first gate**: writing a NEW qa script into the workspace
  was blocked ("looks like an edit to an existing artifact"). Reuse
  the existing qa-pass script path from the prior pass.
