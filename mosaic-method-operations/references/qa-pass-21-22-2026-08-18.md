## Pass 22 — wiring orphaned gates (the durable lessons)

- **Wire at the natural mutation point, not just CI.** contract_sync_gate
  now runs post-flight inside surgical_gate.apply() for CONTRACT/manifest/
  harness-registry/adapters edits. Falsified live: v9.9.9 title write →
  REFUSED.
- **dispatch_gate → MCP tool `mosaic_dispatch`** (8 tools total): the
  WHO+WHICH-model join exposed to any harness. Live: GO, substrate
  selected, admission RUN_NOW, append-only record.
- **Refusal must restore disk.** The FIRST version of the wiring refused
  contract-breaking edits but left the poisoned text on disk; the refused
  v9.9.9 title got COMMITTED. CI (run 32169758442) caught what the local
  battery passed, because contract_sync's own selftest injects drift and
  found the tree dirty. Fix mirrors the D-S2 pattern: atomic restore via
  same-dir temp + os.replace on the refuse path. General rule: an audit
  row saying "refuse" while disk holds the edit is a lie.
- **Selftest isolation must not clobber the CLI.** Wrapping `__main__`
  with the tempdir pin made every invocation run selftest (MCP tool
  returned SELFTEST output). Pin the DB INSIDE the `--selftest` branch.
  Rebinding the module global in `__main__` scope works because connect()
  reads it at call time.
- **Selftest pollution is recurring** (QA-10 D2 → QA-22): 85 of 93 prod
  dispatch rows were fixtures from CI batteries. Purge criteria: fixture
  task-texts, non-T-id keys; keep T-id records. Prove isolation with
  before/after row-count delta = 0.
- **0-byte DB twins under ledger/** are migration residue (a `migration`
  actor event at the same timestamp as the twin's mtime confirms); code
  writes stores/ only. Verify no writer greps clean before deleting.
