## 1. macOS system cron dead host-wide — canary falsification recipe

Symptom: crontab entries valid, `pgrep cron` shows the daemon alive, but
nothing fires (volley silent 40 min while the entry sits in `crontab -l`).

Falsify with two canaries (both must land within ~70 s):

```
crontab -l > /tmp/ct; echo "* * * * * touch /tmp/cron-canary-tmp" >> /tmp/ct
echo "* * * * * touch /<workspace>" >> /tmp/ct; crontab /tmp/ct
sleep 75; ls -la /tmp/cron-canary-tmp /<workspace>
```

Both dead = cron dark host-wide (rules out TCC on a single directory).
ALWAYS strip the canaries from the crontab afterward.

Fix path (uptime law — launchd is the scheduler of record):
1. Write the LaunchAgent plist (`StartInterval`, `RunAtLoad`), `plutil -lint` it.
2. `launchctl bootstrap gui/$(id -u) ...` is BLOCKED from inside the the operator agent
   gateway (persistent-job safety). Hand the principal the one-line bootstrap
   command for a separate shell; plist sits on disk until then.
3. Interim so the cadence never lapses: a the operator agent-cron watchdog job runs the
   tick (the operator agent scheduler fires it, not system cron).
