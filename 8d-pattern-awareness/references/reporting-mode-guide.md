# Reporting Mode Guide

This guide collects the reusable rules for polished 8D snapshot reports, comparison reports, and trend reports.

## When to use
Use this mode when the user wants:
- a polished snapshot
- a recurring report
- a baseline/comparison/trend view over time
- a quick-win style summary that still feels calm, premium, and readable

## Output shape
Prefer a condensed report layout:
- **Overview:** one strong line that names the day or period
- **What is happening:** 2 to 4 bullets
- **What is getting in the way:** 2 to 4 bullets
- **What is still holding:** only if supported by the evidence
- **8D signals:** only the relevant dimensions
- **What would help most:** one concrete action
- **Watch-outs:** only if needed
- **Confidence:** high / medium / low with one short reason, placed after watch-outs so the core read lands first

Choose the report shape explicitly:
- **Baseline snapshot** when there is no prior comparison point
- **Comparison report** when there is a previous snapshot or note to compare against
- **Trend report** when there are 2+ time points and a real direction of change is visible

## Tone and pacing
- Keep the tone calm, factual, and compact.
- Make the report a little more motivational when the day can still be shaped by a better next step.
- Keep the overview readable and compact; do not inflate it into a paragraph wall.
- Do not repeat the source note back to the user.
- Translate the note into meaning, impact, and next steps.
- Keep the layout compact rather than spread out.
- Avoid thick black section headers and heavy block fills.
- Use soft dividers and restrained labels instead of loud bars.
- Let content flow naturally across the page; do not create large white gaps.

## Live dimension cards
- The dimension recommendations block must be synthesized fresh from the day’s actual 8D signal map.
- Each card should show the signal it is answering before the specialist judgment.
- If the cards read the same across days, that is a bug, not a style choice.
- Each card should begin with the current signal, then the specialist read, then the next step.
- Do not let the cards collapse into generic wellness tips.
- If a process note is needed, keep it in the skill/reference layer, not in the user-facing report copy.

## Quick-win framing
- Write each dimension card as if an elite specialist for that dimension reviewed the evidence and drafted the next step.
- Translate each specialist judgment into a small practical step the user can actually use today.
- Regenerate each day’s cards from the current signal map rather than copying a static template.
- If the user corrects the visual feel, treat it as a layout-and-palette fix, not a content rewrite.

## Palette and rendering rules
Before rendering or recoloring a report:
- confirm which documented brand palette is the source of truth
- map the report accent(s) to the exact documented hex values
- do not infer color from memory when a design doc exists
- if the user says a delivered color is wrong, treat that as a palette-source mismatch first
- preserve the approved layout and only change the requested field(s) unless the user explicitly asks for a redesign
- if the page feels too centered or cramped, rebalance the page distribution before tightening the text block
- keep line spacing readable rather than over-expanded

## Hero quote policy
- Use only exact, attributable quotes from a fixed bank or verified source.
- Show the author alongside the quote.
- Do not paraphrase, style-match, or invent motivational quotes.
- If a quote cannot be verified, omit it.
- Choose quotes through the documented process used by the report quote policy reference.

## Flow-first layout
- Prefer breakable section blocks over forcing every card to stay intact.
- Let content flow across pages instead of creating large white gaps.
- Keep related content grouped, but allow natural page breaks when a card would otherwise waste space.
- Avoid making every card `page-break-inside: avoid`.

## Reporting lifecycle
When reporting is recurring:
- keep the same window length if possible
- compare like with like
- carry forward the last baseline explicitly
- only call something a trend after at least two real comparisons or three visible points
- if the window changes, label the comparison as approximate

## Verification
- The report is skimmable and premium-looking.
- The dimension cards are regenerated from the current signal map.
- The layout feels full enough without becoming crowded.
- The confidence line is placed after the core read.
- The output does not invent longitudinal certainty from a single note.
