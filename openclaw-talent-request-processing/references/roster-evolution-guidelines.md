# Roster evolution guidelines

Use this when the user wants to *reassign or enrich* an existing fleet rather than create a new fleet from scratch.

## Core rule
Prefer **evolving existing agents** over spawning new ones whenever the roster already contains a viable match.

## Roster scope
Check all relevant inventories, not just the active the operator agent-facing roster:
- active roster
- inactive roster
- archived / lineage roster
- any OpenClaw-specific roster exports or dashboards

If the ask references "the roster" in a broad sense, assume the full OpenClaw fleet unless the user narrows it.

## What to preserve
- agent lineage and provenance
- original role/family/source status
- archived vs active status
- source skills/personality as the baseline

## What to change
Instead of generic labels like "top tier university", attach:
- a **specific university stack**
- a **methodology lens** tied to that university
- the relevant skills / credentials / operating style for the role

Examples of methodology pairing:
- liberal-arts / synthesis / systems framing
- engineering / rigor / optimization
- research / evidence / publication discipline
- clinical / triage / safety-first reasoning

## Decision heuristic
1. Find the best existing agent by role, family, and roster source.
2. If the agent is close enough, **enrich** it with the new credential/methodology stack.
3. If no fit exists, create a new agent only as a last resort.
4. Document the reason the agent was evolved rather than recreated.

## Common pitfall
Do **not** collapse all universities into one generic prestige bucket. The user wants the methodology to vary by school because the school is being used as an operating brain model, not just a status signal.
