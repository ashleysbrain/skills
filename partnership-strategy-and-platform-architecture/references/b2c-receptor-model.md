# B2C Receptor Model and Multi-Connection Architecture

**Status:** User-approved design from 2026-07-07 session.
**Context:** B2C organisms are INDEPENDENT. They connect to multiple B2B organisms simultaneously through the mycorrhizal network. The user controls which connections exist.

## The Receptor Model

A B2C organism has surface receptors (connection points) for different B2B data sources. Each receptor is a binding + channel + coupler + consent:

- **Binding**: OAuth or API authentication to the B2B
- **Channel**: Data pipeline from B2B to B2C
- **Coupler**: Maps B2B data fields to 8D wellness dimensions
- **Consent**: User kill switch (can revoke at any time)

## Upregulation and Downregulation

- **Connecting** to a B2B = receptor upregulation (cell adapts to new signals)
- **Disconnecting** = receptor downregulation (natural, non-destructive)
- B2C continues functioning with remaining connections

## Integration Engine

Multiple B2B data streams integrate through the 8D coupling physics:
- Weighted by source_trust x recency x mutual_information
- Event-driven delta recompute (only touched subgraphs recalculate)
- Disagreements carried as structured signal, not errors
- Overlapping data (HungryRoot intent + Levels outcome) becomes its own metabolic-efficiency signal

## Accuracy Signal (Shannon Information)

The B2C communicates coaching accuracy to the user:
- `I(bound_sources; dim_state) / H(dim_state)` = information ratio
- Gap signal ranks unbound sources by projected accuracy delta
- Cannot be gamed by volume, only by information quality
- Example: "Your sleep coupling accuracy is 67%. Adding glucose data would raise it to 87%."

## The Demand Loop (15 steps)

1. User connects to first B2B (e.g., HungryRoot)
2. B2C coupling physics integrates. Coaching improves.
3. B2C detects GAPS in accuracy
4. User wants improvement. Goes to missing partner (e.g., Levels)
5. User connects. Accuracy jumps.
6. User tells friends about the improvement
7. Friends want DS coaching
8. Friends ask their services to integrate
9. Businesses receive inbound user demand
10. Businesses partner with DS (get B2B organisms)
11. More data sources available to all users
12. Every B2C can connect to more sources
13. Coupling physics gets richer across entire ecosystem
14. Loop accelerates
15. Never ends

## Multi-Connection Conflict Resolution

When a B2C has 5+ B2B connections:
- Competing data resolved by mutual information dominance
- Cross-check retention (never discard, always weigh)
- Graceful degradation under partial channel loss
- Overlapping data becomes its own signal (HungryRoot intent vs Levels outcome = metabolic efficiency indicator)

## Key Distinction from Tethered Models

The B2C is NOT born under a B2B. It is born under the operator agent (or independently). It CONNECTS to B2Bs through the mycorrhizal network. The B2B provides data and capabilities. The B2C owns the integration and the intelligence. The user owns the B2C.
