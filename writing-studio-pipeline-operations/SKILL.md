# Writing Studio Pipeline Operations

Drives the writing studio API (127.0.0.1:port, launchd label `com.ds.studio-api`) for research-backed drafts: Veritas/CRUCIBLE pipeline runs, draft registration, dialectic records. Auth token: `WRITING_STUDIO_TOKEN` in `<agent-home>/.env` (NOT `STUDIO_TOKEN` — that variable exists but is not accepted by the API). Probe liveness with a REAL route (`GET /api/drafts?limit=1` with bearer) — `/health` and `/api/health` return 404 by design; an unauthorized probe returns 401 JSON, which itself proves the service is up.

## Procedure
1. **Create/register draft**: `POST /api/drafts {title, content}` -> id. KNOWN DEFECT: create returns 200 but may silently DROP the body — always verify with `GET /api/drafts/<id>`; if empty, write the body with `PUT /api/drafts/<id> {content}` (PATCH returns 405 Method Not Allowed) and read back again. Draft carries `pipeline: Veritas`, `stage`, `author`.
1b. **Generation endpoints (studio writes, operator does not)**: for any text the principal will publish, the STUDIO generates/revises it:
    - `POST /api/drafts/rewrite {text, instruction}` -> sentence-level `{needs_rewrite, issues, rewrites[]}`; compose final by taking `rewrites[0]` for flagged sentences (strength rewrite/minor), `original` for the rest. The key is `text` NOT `draft_id` — sending `draft_id` yields a 400 "Need at least 20 characters" (the endpoint never sees the text). Parse of the model reply is tolerant (fence-strip + first-balanced-JSON); if a 500 "Rewrite engine error: Extra data" ever recurs, the greedy-regex parse regressed.
    - `POST /api/drafts/document {topic, audience, question}` -> full studio-born DOCUMENT route (research-lab synthesize -> Wernicke compose -> adversarial panel -> Goethe styling -> Bell PDF render). This is the ONLY compliant path for document-class deliverables to teammates/externals. The route fixes thin abstracts via OpenAlex/arXiv enrichment and keeps a custody JSON (every organ touched, run IDs) next to the PDF — a deliverable without a custody record is not studio-born.
    - `POST /api/drafts/comment {source_url, source_author, source_title, post_content, angle?, ground_truth?, post_mode?}` -> studio-GENERATED LinkedIn comment. With `post_mode: true` the SAME route generates the operator agent's own project posts (3,000-char ceiling, project close law, register lock and panel unchanged) — recipe in `references/linkedin-comment-channel.md`. The studio composes from the binding principal comment standard (loaded server-side) with banned-phrase no-reuse priors; deterministic gates (no-reuse, AI-tells, length, author credit, format) run on output with a built-in revise loop (max attempts shown in `attempts[]`); draft + version saved; response carries `gates_passed`, `needs_human`, custody. The route also classifies the REGISTER deterministically (E0 everyday reader / L1 practitioner / L2 engineer / L3 researcher, from author signals + technical density of the post) and instructs the writer to scale technical wording to that level — plain verbs and in-line definitions at E0/L1, paper-level precision at L3; the response carries the register so the board card can render status + level chips (the chosen register must be VISIBLE per card, not just applied silently). Min 100 chars post_content, re-sent on EVERY POST including retries (the route 400s on empty). Full referral-shortlink-to-paste-ready-card recipe incl. the 409 bounce-cap un-park: `references/linkedin-comment-channel.md`. This is the ONLY compliant path for principal public comments — operator-composed base text + studio rewrite does NOT count as studio-written (rejected twice by the principal). With `panel: true`, a successful 200 carrying a complete comment can still report `needs_human: true` — that is the expected posture for principal-public text (the principal posts manually); judge the deliverable by the returned comment text, do not loop retrying to flip the flag. For a correction/re-run of an already-posted comment, put the full correction contract in `angle` (what v1 got wrong verified against the source, that review caught it, in-training posture, what remains open) — the studio composes the graceful self-correction from it.
    - **Debug gate failures from the gate SOURCE, never from error-string guessing.** Import pipeline_api via importlib, call the failing check function directly (`_gg_comment_gate`, `_gg_comment_intrigue_check`) on a candidate, and unit-test the specific regexes it uses (import them from writing-studio/gg_voice.py). Two failure modes found this way that are invisible from the outside: (1) the intrigue check lowercases the body but hook patterns can contain case-sensitive `I` tokens, so a genuine-question hook can NEVER match — normalize the pattern alongside the text (`re.search(pat, low) or re.search(pat.lower(), low)`); (2) the truth check requires >=0.6 token overlap between a self-claim sentence and a gg_self_fact — a compound sentence that appends unrelated clauses dilutes the overlap below threshold. Keep each self-fact claim in its own sentence, carrying the fact's tokens verbatim; questions ending in `?` classify neutral, and an `I cannot answer` phrasing is exempt from the self-claim regex.
    - **Surgical close-out beats whole-draft regeneration.** When a generated draft is 1-3 gate failures from passing, do NOT regenerate: keep the draft byte-identical except the flagged sentences, iterate one gated fix at a time (each pass re-runs the full gate). Converges in <=5 passes where blind regeneration looped indefinitely. Restructure rules learned in flight: a hook sentence that opens with a first-person self-claim fails truth unless it matches a fact — put the mechanism inside a question instead; every factual recap sentence must be immediately followed by a learning anchor or the learning-ratio check flags it.
    - **RE-GATE LAW: every post-panel or hand edit to gated text MUST re-run the binding gate before delivery.** Import pipeline_api via importlib and call the gate function (e.g. `_gg_comment_gate(text, author, priors, ground_truth, self_facts)`) on the final text — a panel-PASS before your edit does not cover the edit. Hand-compressed finals have failed re-gate en masse (char ceiling including header+signature, false built-claims, missing hooks, AI-tells); the gate is never wrong, routing around it is the defect.
    - Before claiming a pipeline is closed or open for a text class, probe `/openapi.json` paths AND read the route's handler in pipeline_api.py — a route name that sounds generative can be a placeholder factory (`/api/publications/write-for` creates draft+calendar placeholders, NOT text).
    - `POST /api/draft/revise {draft_id, instruction}` -> surgical edit ops `{op: replace_text, find, replace, reason}[]`. The revise engine can take 200+s (model wall time) — timeout 600, retry once on timeout. Ops are NOT auto-applied to the stored draft: apply the find/replace pairs yourself, then `POST /api/drafts/<id>/version {content, label}`.
    - Route `POST /api/drafts/<id>/route {target: linkedin_comment}` returns `results: []` (runs ZERO gates — known defect); the operator's own gates are load-bearing, never ceremonial.
2. **Start pipeline run**: `POST /api/veritas/run {idea: <<=2000 chars>, author, output_formats: ["draft"]}` -> `{run_id}`; poll `GET /api/veritas/status/<run_id>` every ~20-25s. Hard cap 20 min (DEFAULT_MAX_DURATION_SEC).
3. **Terminal statuses**: `completed`, `complete_with_quality_issues` (deliverable + flagged warnings, e.g. weak citations), `paused` (engine health gate), `failed`, `failed_stalled` (410).
4. **Paused run**: fix engine health (below), then `POST /api/veritas/resume/<run_id>`. Only `paused`/`awaiting_human_review` records resume; a `failed` record needs a fresh run.
5. **Intermediate state**: run result carries `state_path` pointing at `/tmp/Veritas_process_state_<ts>.json`; read `current_stage`, `stages_completed`, `current_draft`, `citations` from that file for progress and salvageable output.
6. **Dialectic record**: `POST /api/drafts/<id>/dialectic {objection_text, response_text, author}` -> read back via GET. Empty bodies now 422 (correct); `position`/`content` keys map onto objection_text.
7. **Discover endpoints**: `GET /openapi.json` and read `paths` + `components.schemas` — the API surface is large and discovery beats guessing route shapes (stage-advance endpoints do not exist; stage moves happen inside pipeline runs).

## Multi-user auth: real account minting + credential custody
When a human needs studio login and handed-over credentials fail (or none ever existed):
1. **Discover the real auth route from source, never from URL convention.** The login route is `POST /api/auth/login`; the convention-shaped `/auth/login` returns 404 `{"detail":"Not Found"}`. Grep the app source inside the web container (`docker exec <web-container> grep -rn "auth" /app --include="*.py"`) and cross-check `/openapi.json`.
2. **The user store is admin-minted** — there is no public register/signup route. Mint accounts directly in postgres (the `ws-db` container, database `writing_studio`, `users` table) with a bcrypt hash generated by the app's OWN bcrypt stack inside the container, never a hand-rolled hash from a different library or rounds count.
3. **Verify E2E from BOTH paths**: the login POST from inside the container AND from the URL the user will actually type (the tailnet-facing port, not 127.0.0.1). A container-local 200 proves the credentials; only the external probe proves the user can reach them.
4. **Custody**: fresh random password; store only the hash; wipe every plaintext copy on the server after verification; deliver the plaintext exactly once over the user's private DM; offer a reset on demand.

**Never fabricate or guess credentials.** A login not verified end-to-end against the real user store does not exist — invented credentials surface later as a lockout plus a trust breach. On any access-failure report, verify which accounts actually exist in the real store before saying anything about access.

## Engine health gating (runs pause at stage 4/4.5/5 on dead engines)
The run snapshots engine health each stage and pauses naming the dead engine in `health_snapshots` of the state file. Creative/quality fleet: wernicke:port, tawara:port, popper:port, bell:port, goethe:port, luria:port, andreasen/da-vinci:port, hall:port, harvey:port. All KeepAlive-managed launchd agents: a down engine self-relaunches within ~10s (ThrottleInterval). WAIT for relaunch; never hand-start `uvicorn`/`run_server.py` in a shell — an orphan hand-started instance blocks the managed one with `Errno 48 address already in use` and the label flaps.

## Pitfalls
- **'Stage 3 verdict: FAIL' with skeleton `error: Expecting value ...` is a JSON-parse defect in argument_architecture, not a content failure.** All three skeleton variants erroring at parse = the stage emitted malformed JSON; diagnose from the newest `/tmp/Veritas_process_state_*.json` (`stage_results['3'].all_skeletons[].error`), fix the stage's output parsing/prompt (strict-JSON + parse-retry), then start a FRESH run — a `failed` record does not resume. Reproduced across consecutive runs, treat as a pipeline defect to patch, never as an idea-quality signal.
- **One service, one launchd label.** Before installing a KeepAlive manager for a service, grep `~/Library/LaunchAgents` and `launchctl list` for an existing label on the same port. A second label for an already-managed service leaves a dead legacy label; any watchdog still pointed at it pages CRITICAL 'no PID' every pass against a ghost while the real service is healthy — the principal gets paged all night for nothing. Consolidate: bootout legacy label, rename its plist `<label>.plist.disabled-<date>`, repoint every guardian that greps the old label string, verify watchdog `service_has_pid()` True against the new label.
- **Gateway shell cannot bootstrap launchd.** `launchctl bootstrap` from the gateway terminal is blocked (SIGTERM-respawn protection), including through wrappers like `trap "" TERM; bash script.sh`. Drive installs via python3 subprocess calls in a script, or dispatch a leaf subagent.
- **Resume needs the run's own idea.** Construct the pipeline for resume with `VeritasPipeline(state.idea)` — `VeritasPipeline(state)` raises TypeError (missing positional `idea`).
- **Pipeline output is not the deliverable.** A full Veritas run produces a long cited essay exploring the idea space; if the assignment is a direct answer to a specific post, the human-directed draft + adversarial seat review is the artifact, and the pipeline run is process validation. Deliver the direct answer in-channel first.
- **Quality warnings are honest signals.** `complete_with_quality_issues` with 'weak/phantom support' citations means the pipeline flagged its own citations; do not represent that output as fully verified.
- **The rewrite engine enforces STYLE, not TRUTH.** It flags conversational framing and comma splices but will preserve a factually false claim (it can flag a sentence and its replacement still keeps the untruth). The revise engine accepts truth corrections via instruction, but YOU must verify claim-state afterward (grep the output for the false phrase). Never let text claim unshipped work as shipped — audited / build-list-queued / deployed are three different states and only the true one may appear.
- **Filing is not authorship.** Registering operator-written text as a draft and gating it does NOT make it a studio product; when the process requires studio-written output, the rewrite/revise engines must do the composing and the version chain must show it. Operator hand-edits on top are a last resort and get labeled as such.
- **The studio fixes its own defects (self-heal, don't wait on the sibling).** When a studio endpoint 500s, localize the defect in pipeline_api.py, patch it, unit-test the fix offline on the exact failure payload, restart the service, and re-verify live against the staged repro — the whole repair belongs to the operator that hit it. A tolerant-JSON extractor (fence strip -> direct loads -> raw_decode scan over [ and { openers) passes 7/7 malformed-output cases including trailing-prose and two-array outputs. SCOPE LIMIT: self-heal means pipeline defects in the operator's own surfaces (parse bugs, gate wiring, drafts) — building NEW endpoints/engine features stays the engine lane's job (file a spec'd build order on the bus instead, even under fix-it-yourself pressure).
- **Slug-id stores reject implicit ids on direct INSERT — set explicit ids on every store in this family.** drafts.db drafts AND boards.db `items` use slug ids (an INSERT omitting `id` lands the row NULL-id'd — saved but unreachable); boards.db `items` additionally needs an explicit `seq` (a NULL-seq row never renders on the board) and has NO `created_at` column (the timestamp column is `updated_at`). After any direct INSERT, re-query `WHERE id IS NULL` (expected: 0 rows).
- **A body-less 500 from a studio route can be an import-time SyntaxError in pipeline source — check source integrity before debugging route logic.** An interrupted stash-pop leaves files `UU` (unmerged) with `<<<<<<< Updated upstream` / `=======` / `>>>>>>> Stashed changes` markers embedded in `pipeline_api.py` and `writing-studio/gg_voice.py`; the running service keeps serving its stale in-memory copy while every fresh import dies, so live behavior and disk state disagree. Diagnose: `git status --short | grep '^UU'`, `grep -n '^<<<<<<<' <file>`, `python3 -m py_compile <file>`; surface the hidden traceback by importing pipeline_api in a scratch process and calling the failing route's internal function directly (the HTTP 500 body carries none — and a syntactically clean pipeline_api still 500s when a handler's transitive import, e.g. `from gg_voice import ...`, hits the broken file). Resolve: keep the committed HEAD side of every conflict block (HEAD is canonical); union-merge a block whose stash side purely ADDS code HEAD lacks (drop markers only). A file can also carry an ORPHAN half-block (a `=======`/`>>>>>>>` pair with no opening `<<<<<<<`) — the full-block regex resolves the rest and py_compile then fails on the survivor; those lines are usually a pure stash-side ADD of a new function: union by hand, drop the two markers, re-compile. Then py_compile, `git add` to clear UU, `launchctl kickstart -k gui/$(id -u)/com.ds.studio-api`, re-verify.
- **GET returns HTML-escaped text** (apostrophes as `&#x27;`) — `html.unescape` before comparing or applying find/replace, or every match silently fails.
- **Readback `match: False` with equal char counts is whitespace/quote-shape drift, not a failed save** — compare with `.strip()` and unescape before declaring a PUT mismatch; only a length gap means the save actually failed.
- **LLM 5.x hybrid reasoning returns `content:""` with the text in `reasoning_content`** — any generation route must extract content -> reasoning_content fallback, raise `max_tokens` (700 is consumed by reasoning tokens), and pass `thinking:{type:disabled}` for non-reasoning tasks (latency 113s -> 14s when disabled). Symptom: drafts saved with empty content while metadata claims `generated_by: glm-5.3`. A 502-class guard must refuse to save a draft when generation is empty.
- **Truth gate is BUILT into `/api/drafts/comment` — but the operator claim-check stays load-bearing.** The route now extracts first-person-we claims and fails them against caller-supplied `ground_truth` (list of verified facts); absent ground_truth = paper-only posture where ANY self-referential claim fails. This catches fabrication classes the style gates miss, yet a gated-PASS comment can still assert a paper finding the source excerpt does not support — keep claim-checking every we-assertion AND every paper-claim against the source text; unmatched = withdraw, do not hand-fix.
- **Operator-authored documents are invalid regardless of QA quality.** When the principal orders a document (for a teammate, expert, or public), hand-writing the markdown and pandoc/Chrome-rendering it is a protocol violation even if every citation checks out — the check is lineage (did a specialist produce it?), not quality. A missing studio route is a build order to dispatch, never a reason for operator hands; withdraw hand-made artifacts on discovery and re-deliver studio-born with custody record.
- **Document-class deliverables need a design/legibility seat and a links check — unanimous prose-QA passing a paragraph wall is the wrong standard, not a wrong document.** A panel checking only fact/truth/voice/reuse/tells says nothing about whether a human can READ the artifact. Document expectations: visual decision tree or flowchart for the core structure, phi-proportioned layout as structure (61.8/38.2 grids, type ladder) not decoration, real graphs where claims are quantitative (simulation-computed, honestly labeled schematic otherwise), callouts/takeaway cards over prose walls, and a clickable further-reading block with canonical doi.org/arxiv.org URLs — every link HTTP-verified or flagged with a reason. The best permanent QA regression input is the rejected artifact itself: re-run it through the new seat and confirm it fails.
- **`/api/drafts/document` can silently return a skeleton in place of a letter — always verify generation content before delivering.** Wernicke compose (`:port/v1/compose`) degrades to `degraded_deterministic` assembly when the LLM provider chain fails (LLM empty-content flakiness): the draft stores HTTP 200 with outline headings, digest echoes, `(composed from supplied context)` placeholders, or a ~90-char canned body, `review_state: pending` regardless. Check `generation_mode` in the custody JSON next to the Bell PDF and the draft content length — `degraded_deterministic` + short/placeholder body = retry, not deliver. Diagnose the provider with a direct minimal curl to the chat-completions endpoint (LLM needs `thinking:{type:disabled}`; an intermittent empty `content` is the flake, not a dead key), then re-run the route.
- **Root cause of letter-sized degraded compositions: the document path gives each LLM provider ONE attempt clamped to 60s** (`generate_technical_document` walks the failover chain with `timeout=min(60, remaining), max_attempts=1`). Tiny prompts finish in ~2s; long-prompt letter compositions run past the clamp, return None, and the route silently degrades. Re-running the route usually reproduces the failure. The working bypass for personal letters: drive the SAME engine directly — import `wernicke.core.semantic_network._resolve_providers`/`_chat_json` from the engine's `src/` tree, compose with a purpose-built system prompt (letter voice, grounding facts, banned tells), your own retry loop, `thinking` already disabled inside `_chat_json`. Letter composed in ~9s where the route failed 4x. Then run `comment_agent.run_panel` manually and render via Bell — lineage stays studio-born (same engine, same seats), only the wrapper is bypassed.
- **Full-paper-size compositions (multi-thousand-char findings, 10+ outline sections) fail the same 60s clamp even while small probes succeed — compose in two half-payload passes and stitch.** Split outline and key_findings into halves, give BOTH passes the full source list (citation context must never split), call `generate_technical_document` directly per half (~35-55s each, inside the clamp), concatenate `sections`, keep pass-0's headline/subtitle. Verified: 11 sections / ~14k chars / zero placeholders where the single-shot route returned byte-identical skeletons across four attempts under dropping load (size, not load, is the trigger). Feed the stitched body into the manual panel loop: `run_panel` needs the REAL `_DOC_VOICE_STANDARD`/`_DOC_VOICE_EXEMPLAR` (grep pipeline_api.py near their definitions — passing None crashes `seat_voice_checker`), and Bell `:port/v1/render` wants `title` (not `headline`) + `brand_name` + palette keys `secondary|accent|teal|font_family|font_display|font_mono` (butterfly `#f5c518`, Manrope/Sora) — a wrong-shape payload returns `pdf_error: None`, not an engine fault. Full recipe + studio stores map: `references/document-route-deep-run.md`.
- **Voice-seat and fact-seat failures on manual panel runs are INPUT defects, not draft defects.** The voice seat enforces the organism-author standard (first-person singular I/my from the named organism, never we/our) — when compose returns we/our, patch the SPINE (the topic/question strings carry "Write in first-person singular (I/my) throughout. Never we/our.") and re-compose; never hand-convert pronouns. The fact seat verifies claims against `source_text` — build it with [:1200]-char source abstracts (the pipeline contract width); a [:400] truncation cuts the supporting quote and honest, well-grounded claims fail UNSUPPORTED with an empty quote field. Claims drawn from the paper BODY (theory sections, methods, contested-literature arcs) verify EMPTY against abstract-only source_text even at full width — extract verbatim body passages and append them to source_text as labeled quotes (strip markdown link syntax `[text](url)` to plain text before whitespace-collapsing, or quoted anchors never match). UNSUPPORTED + empty quote on a body claim means the seat cannot SEE its evidence, not that the claim is false. UNSUPPORTED on an attributed QUOTATION (a phrase presented as the paper's own words) means the composer fabricated the quote — grep the source for the exact phrase; at zero hits it is invented and must be struck or hedged in the next compose round, never hand-patched into support. Absence-claims about a source ('the paper never asks the system under assessment', 'does not model X over time') can never be quote-supported because the seat verifies by quote-match — reframe them in the next compose round as the author's own first-person observation, never as claims attributed to the paper.
- **Bell `:port/v1/render` accepts `html_override` (the the specialist engine lane): art-directed HTML rendered verbatim through the Bell path.** When the default template fails the design seat's structural probes, build the design HTML against the probe contract — >=3 `<svg` figures, elements classed `callout` with a `key-takeaway`/`sidebar` label, a flex/grid layout with literal 61.8%/38.2% columns, at least one `href="https://arxiv.org/` or `https://doi.org/` link, no `<p>` over 900 chars, and "phi"/"1.618" declared — then pass it as `html_override` so the design seat judges the real rendered artifact. Match figures/callouts to sections by SUBSTRING, not exact heading equality: compose output headings drift from the outline and exact-key dicts silently drop every figure. Give every SVG explicit `width`/`height` attributes — `viewBox` alone renders collapsed in the Bell PDF and the art-direction judgement reads collapsed figures as absent. Figure captions must carry attributable axes and a named source line; "composed from cited literature" fails as unattributable — and each figure needs its OWN unique caption with its own verified canonical link (shared captions, or one link standing in for every source, fail traceability). Chunk body paragraphs near 620 chars (about 8 rendered lines), not merely under the 900-char wall probe — the seat judges visual break by line count. When the design seat returns `seat-parse-defect`, the verdict line is unreliable — parse the numbered EVIDENCE lines for the real per-probe results and fix the failing numbers before touching content. Full probe checklist: `references/document-route-deep-run.md`.
- **Keep the synthesis spine as ONE versioned JSON consumed by every stage script.** When the principal corrects the thesis or audience frame mid-iteration, edit the spine file (topic, question, outline, digest, voice constraint) and re-run split-compose + panel from it — never fork parallel candidate drafts, and never let a stage script carry its own inline copy of the directive (two sources of truth diverge silently between rounds). principal mid-iteration context is ADDITIVE input to fold into that one spine (kill in-flight runs on the superseded spine; keep completed drafts in drafts.db as evidence, never as menu options) — do not present the principal a candidate A/B choice: the organism composes one synthesis and the panel gates it; the principal supplies context, not selections. Before deleting a scratch intermediate, grep the stage scripts for its filename: downstream scripts read earlier stages' outputs by path and a clean-up kills the next run at import.
- **Fire document-route runs as background from the START, and judge success by the out-file `EXIT=` line, never by the completion notification.** The route runs 400-500s+; a foreground terminal call times out client-side while the server keeps processing, and a naive re-fire double-runs the pipeline. The wrapper `... ; echo EXIT=$?` makes a crashed script surface as 'completed normally (exit 0)' — the notification describes the wrapper, not the run; open the out file and read the traceback/EXIT line before drawing conclusions. Re-read the verdict JSON fresh at each completion too — seat evidence quoted from a previous round is stale and misdirects the next repair.
- **`run_panel(..., artifact_kind="document")` is fail-closed on design evidence: without `design_html` the design seat auto-REVI**ses ("design evidence missing: no rendered HTML supplied"), so 5/6 PASS still reads non-unanimous. Render FIRST via Bell `:port/v1/render` (title/subtitle/sections/theme/doc_type; returns html_path + pdf_path) and pass the HTML string as `design_html`. Also required keyword-only args: `exemplar` and `standard` — for a personal letter, write a letter-appropriate standard; the pipeline's `_DOC_VOICE_STANDARD` is organism-voice and wrong for founder-personal text. One legitimate exception: for a plain-text letter the design seat probes phi-columns/SVG/citations (genre mismatch) — a design REVISE on those probes with all five substantive seats PASS is deliverable, stated as such.
- **Intermittent `sqlite3.OperationalError: disk I/O error` across UNRELATED databases (plus heredoc/mktemp 'No space left on device') is a full root disk, not a DB defect.** Check `df -h /` first; when capacity is 100%, freespace work comes before any pipeline diagnosis — the same error will keep appearing on every sqlite open until space exists. Clearing `<agent-home>/cache` and Bell render outputs is the quick first move.
- **Confirm a generative engine's output tracks its input before building on it.** A silently-wrong schema (pydantic dropping payload fields) returns canned demo content with HTTP 200, which looks like engine success and poisons every downstream lineage step. Probe with a rich payload, verify the output reflects it, and confirm empty input is REFUSED rather than answered with the demo (the Wernicke /v1/compose canned-content class).
- **Multi-model parallel retry harness for comment drafting** (`/<workspace>` + `gg_retry_jobs.py`): each job runs one lane per model (glm -> deepseek-flash -> nemotron ladder), single-model sequential within a lane, first full-gate PASS wins and writes a FINAL file. Known constraints: glm-5.3 needs max_tokens >= 16000 (hidden reasoning starves smaller budgets, content comes back empty); NIM lane must use entitled models only (probe the 82-model list when 404s appear; mistral-large-2 is NOT entitled); the harness prompt must carry the canonical header, the five-element signature block, dash bans, and credit form verbatim or format-failure classes recur. **After a lane converges to best 1-3 fails, close it out surgically** (rules above) rather than relaunching the lane. **Register every FINAL into the studio system**: drafts.db row (pipeline='comment', metadata with persona='gg', gates_passed=True, source_url, receipt, char_count) — without persona='gg' the archive rebuild skips the draft; then mint the receipt via gates/task_ledger.py. **Before acting on a duplicate lane completion, grep for the existing FINAL/receipt** — lanes launched before a surgical pass can report converged drafts for already-delivered work.
- **The AI-tells scanner bans em dashes in public text, with ONE exemption: the canonical "— the operator agent" sign-off line.** Studio-generated rewrites introduce em dashes freely; run the tells scan AFTER every studio pass and route any hit back through `/api/draft/revise` ("remove the em dash in the sentence about X, change nothing else") rather than hand-editing — the operator's own gate, the studio's own fix. A scan reporting exactly one em_dash located in the signature line is a PASS (scan the body-only or confirm the hit is the sign-off); a body em dash is always a fail.
- **The delivery seam is part of generation: stamp + sync on post.** Hand-fixing a card into the board while the drafts.db row keeps the pre-fix text with `delivered` unset leaves the rotation corpus empty — every variety window (shape rotation, marker rotation, no-reuse priors) reads ONLY delivered drafts, so consecutive comments drift back to one skeleton and read as same-old-style to the principal even though the panel passed them. When a canonical block is posted, the SAME action stamps the draft row delivered AND syncs the final hand-fixed text into that row; the draft row is the single source of truth the rotation engine reads, not the board card. Mechanics: drafts.db has NO source-url/link column — locate the row by title fragment (the route titles rows `the operator agent comment — <source_title> (<author>)`) or `pipeline='comment'` recency, then set `stage='delivered', review_state='accepted'` and overwrite `content` with the final text; re-read the row length to confirm the sync landed.
- **Log every comment QA pass as a qa_tracking row in the LIVE `writing-studio/linkedin_metabolism.db`.** Columns: `content_path, content_type, reviewer_agent, reviewed_at, ai_telltale_count, em_dash_count, banned_phrase_count, human_voice_score, factual_accuracy_score, overall_pass, issues_found, revision_number` — there is NO task_id/ts/kind/subject/verdict column (free-text context goes in `issues_found`).
