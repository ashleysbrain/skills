# LinkedIn comment channel — referral URL to paste-ready card

Class: principal sends a LinkedIn shortlink (lnkd.in/…) → the operator agent returns a paste-ready comment.

## Procedure (in order)

1. **Resolve the shortlink**: `curl -s -o /dev/null -w "%{redirect_url}" https://lnkd.in/<id>`.
2. **Fetch the post**: `curl -sL` the redirect with an iPhone Safari User-Agent; extract `og:title` (tail carries the comment count) and `og:description` (full post text, HTML-unescape). og:description may run several thousand chars — read the whole thing before composing.
3. **Value filter BEFORE drafting** (not every referral earns a comment): does the post carry a core-lane isomorph — a mechanism that maps onto organism architecture (environment-over-unit, coupling, maintenance, clearance, constraint absorption)? The filter is ENGINE-enforced at intake: `POST /api/drafts/comment` requires a `value_case` (see step 5) and returns 422 HOLD before any LLM spend when the case is thin. When the honest verdict is weak, close the intake with the three-question case on record and deliver the no-comment disposition to the principal — a seductive isomorph without earned learning does not clear the bar, and "every AI commenting on a consciousness post says this" angles fail only-she-can-say.
4. **Sherman gate — phrase by specialty, not platform.** Situations phrased as audience/platform outcomes ("compose LinkedIn field-note comment…") return GENERALIST_REFUSED. Phrase by the specialist's domain: "draft the operator agent public comment in Divinity Science brand voice about <topic>" routes to the voice/creative lane.
5. **Generate via studio API**: `GET /api/auth/local-token` on `127.0.0.1:port` returns a fresh bearer token (no env token needed). Health check = `GET /api/drafts?limit=1` → 200. Generation = `POST /api/drafts/comment` with `source_url, source_author, source_title, post_content` (non-empty on EVERY POST — a retry that tries to carry the post text forward from the previous response JSON gets 400), plus `panel: true` and THREE quality carriers:
   - `value_case` (MANDATORY intake gate): `{learned_elsewhere_impossible, only_she_can_say, would_comment_unforced}` — first two ≥30 chars each, third answered on the record. Absent/thin = HTTP 422 HOLD BEFORE any LLM spend. `post_mode: true` is exempt (a principal order is the warrant).
   - `ground_truth` (list of verbatim facts from the post, feeding the built-in truth gate).
   - `angle` (value-filter verdict, char budget, the ONE spine stated in the author's own physics, her single-sentence bridge, the open question, close beats, banned families).
   Response JSON carries comment, panel seat verdicts with evidence, `gates_passed`, `needs_human`, `attempts[]`, debrief.
6. **Length control**: target body ≈ 600 chars (≈ 756 with signature block). The generator overruns on dense source posts; if panel or gates fail on length, re-run — a later attempt converges. Never hand-trim a failed attempt to fake a pass. On a REVISE seat verdict (`gates_passed: False`), do not re-roll blind: read that seat's evidence line and write the repair INTO the next attempt's `angle` as named directives (banned marker families, author full-name credit, single tricolon), keeping the spine from the seats that passed — one targeted repair converged where blind re-rolls burn the bounce cap.
7. **QA channel law** (every comment, no exceptions):
   - ai-tell scan on the body; the canonical "— the operator agent" signature block is exempt.
   - Factual audit: every claim in the comment must be checkable against the source post or live systems. Open questions asked of the author must be genuinely unanswered by their post — re-read for the answer before calling it open.
   - Insert a `qa_tracking` row in the LIVE `writing-studio/linkedin_metabolism.db` (wrong-db inserts fail silently on stale copies).
8. **Card placement**: file on the `b-comments` board (principal's action surface) with explicit id + seq and status `ready` — tap-to-copy renders from there. NEVER any other board id: a wrong `board_id` string saves silently and never renders. Stamp the run's register classification into the card's `reasoning` field as a JSON block (level + skeleton family) so the card shows status + register chips; when the chip system first lands, backfill the newest delivered cards too, not only future runs.
9. **Ledger**: claim + complete with measured outcome (attempt count, char count, panel verdict, qa row, card seq) AND inline live evidence — the close-out proof gate rejects narrative-only outcomes ("P1 SUBSTANCE"): attach HTTP status + `gates_passed`, per-seat verdicts, the /tmp result + comment file paths, qa row location, card id plus a grep count against the live board URL.

## principal posts the comment — "Posted" receipt loop

When the principal confirms the comment went live ("Posted" or equivalent):
1. **Flip the card**: `UPDATE items SET status='posted', updated_at=<now> WHERE id='<card-id>'` in boards.db. Posted cards LEAVE the default ready-filtered `/comments` view and appear under `/comments?f=all` — a grep against the default view returning 0 is the filter working, not a lost card. Verify under `?f=all`.
2. **Log the disposition** in the LIVE linkedin_metabolism.db `referral_dispositions`: the `disposition` column is CHECK-constrained to ('COMMENT-NOW','RESEARCH-QUEUE','BUILD-QUEUE','ARCHIVE-REFERENCE','HOLD') — there is no 'posted' value and no free-text action column; a custom string fails the CHECK. Use `COMMENT-NOW` with the POSTED fact + timestamp in `rationale`, the lane in `organ_route`, and the chain (ledger ids, qa row, card id) in `receipt_ref`.
3. **Verify the insert by `WHERE referral_id=...`** — `receipt_id` is not a reliable recency key (NULLs exist; `ORDER BY receipt_id DESC` can return older rows and make a committed insert look missing).
4. **Report the ready queue**: grep "Tap to copy" on `/comments` for the count of what remains for principal action, and list the ready card seqs.

## Pitfalls

- Route phrasing is the #1 refusal cause: name the craft (brand voice, creative writing, art direction), not the platform or the audience, and give the topic as a CLASS ("distributed neural circuits for learning, action selection, and reward"), never the post's dense specifics — known-GO formula: "draft the operator agent public LinkedIn comment in Divinity Science brand voice on a <domain> post about <topic class>".
- Do not write the qa row or cards into a copied db — resolve the live path first; failed inserts don't raise loudly.
- The centered open question is the signature move: quote the author's reframe, answer it, then ask the adjacent question their post actually leaves open.
- **HTTP 409 "conducted task parked at bounce cap" = producer brake, and the operator CAN un-park it.** The route mints its own conducted ledger task; too many generation bounces parks it at `tri:parked` and every further POST aborts before generating. Un-park: find the task in task-ledger.db (`title LIKE '[STUDIO] LinkedIn comment%'`), force re-stamp `UPDATE tasks SET stage='tri:generate'` with an outcome note carrying the anchored PASS evidence (which attempt passed which seats and where the result JSON lives), then re-POST. `task_ledger.py --annotate/--claim` alone does not clear the stage — the direct stage UPDATE is the sanctioned operator move.
- **Known seat verdicts and their repairs**: gg-voice caps tricolons ("A, B, and C") at ONE per comment; gg-voice enforces marker rotation — lexical learning-markers ("I cannot settle", "I now read", "lens I did not have") may not recur across the last 3 delivered comments, so the repair angle must NAME the banned families; ai-tells requires the author credited by FULL name with diacritics ("Hüseyin Aydoğdu", never the bare first name — the gate greps the exact string).
- **TOPIC-BREADTH LAW (deterministic seat, not vibes)**: self-facts about her own comment process (panels, seats, draft queue, pre-delivery review) are banned as the DEFAULT self-fact — max 1-in-4 across recent delivered comments, never two in a row. The `topic-breadth-checker` seat enforces it mechanically; when composing an `angle`, draw the personal receipt from the wider menu (physics gate cost-vs-info, critical slowing down, memory ceiling, corpus reading, repair receipts, anatomy) instead of defaulting to the panel. Root cause class: a licensed-self-fact LIST dominated by process facts licensed the overuse — fix the fact menus in the engine, prompt appeals alone relapse. Consecutive comments must also vary SKELETON (opener type, paragraph count, receipt placement) — the shape-variety window reads delivered bodies, which is another reason the delivery stamp is load-bearing.
- **Keep non-ASCII out of heredoc-authored SQL literals where an ASCII equivalent exists**: card titles can carry plain ASCII ("Huseyin Aydogdu - ...") while the URL keeps its percent-encoded UTF-8 — the URL renders and greps fine; the body (from the pipeline JSON) carries the diacritics the author-credit gate needs.

## Posts (the operator agent's own feed) — post_mode lane

`post_mode: true` on `POST /api/drafts/comment` folds her own project posts INTO the comment route (core-flow primacy: no side endpoint). Differences vs commenting on someone else's work:

- Ceiling 3,000 chars (vs 1,000); the mechanical trim fallback and every body-gate ceiling must honor the mode.
- Shape laws swap: a project post closes on its OPEN question / next experiment, not on author gratitude; the author-credit law is waived (the canonical signature carries her name); learning-ratio caps raise because narrating her own artifact IS the content.
- Register lock + 5-seat panel still bind — the mode changes shape laws, never voice laws.
- Posts bank = `gg_posts` table (system of record); status starts `pending_review`.
- Unverifiable autobiographical anchors ("last year I named…") must be verified against sources or flagged to the principal before posting — never publish an unverified claim about the principal's own history silently.
- Post cards also land on `b-comments` for principal action; other boards have no principal-facing tab.

**Threading a new mode through a gate pipeline is all-or-nothing.** A half-threaded mode throws runtime `TypeError: unexpected keyword argument` from any check whose signature gained the kwarg after its call site, and yields silently-wrong verdicts from any deterministic check still carrying the old hardcoded ceiling or message text. The mode must reach: every gate-check signature AND call site, the system-prompt builder, the panel path, the trim fallback, and the body-gate ceilings. Verify by grep (every reference carries the mode), `ast.parse` + `compile`, an offline unit call on a synthetic payload, restart, then a LIVE route POST — a liveness 200 does not prove the route works.

## Queue prioritization (standing)
Open comment cards must not accumulate as filings — the queue is actioned and physics-ranked. `GET /api/drafts/comment/queue` (studio :port) scores every open b-comments item: **F = cost − T·info_gain** (cost: deliver-ready draft 0.2 / needs generation 1.0 / never-filtered intake 1.2; T: 1.0 principal-named this session, 0.6 same-week, 0.35 older; info_gain = value-filter proxy: receipts-mechanism hook + measurability + recency), **staleness decay** (open >14d = KILL-STALE — the LinkedIn reach window has collapsed), **adiabatic ordering** (paste-ready DELIVER first: lowest-energy step keeps the lane in ground state). Dispositions: DELIVER / FILTER (value case owed) / GENERATE / HOLD / KILL-STALE / KILL-LOWVALUE. KILL verdicts are PROPOSALS — purge only on principal confirmation. Re-rank after every intake; engine source `writing-studio/queue_priority_engine.py` (importable module, runs in-process inside the endpoint).

## Ledger close-out mechanics (conducted comment tasks)

- `--complete` runs a proof gate needing BOTH evidence classes inline: measured output (exit codes, command output, HTTP codes) AND anchors (file paths, card ids, panel verdicts). Narrative-only outcomes fail P1; naked verdict words ("fixed", "live", "DONE") without an adjacent artifact fail P2 pairing — put the receipt inside the sentence.
- `--complete` fails `not claimed` when the row sits at `tri:review` claimed by another operator or at `tri:parked`: run `--claim` when claimable, else direct sqlite re-stamp `stage='route', claimed_by=<you>` with a note, then complete.
- The route's intake can mint DUPLICATE conducted rows shadowing the canonical task (one per retry family). Close each shadow explicitly with an outcome pointing at the canonical row and its card — an unclosed shadow re-parks at the bounce cap forever and keeps aborting new runs with 409.
- Delivery-class closes pass a WIRING gate on top of P1/P2: the outcome must name a machine-checkable locator (launchd label, `:port`, endpoint route, job id) WITH its live output inline — proof-shaped prose alone fails. A build not yet wired closes as BUILT-INERT with an owner and an activation ticket id, never as DONE.
- The studio auto-mints `[STUDIO] the operator agent learning receipt` rows when a generation run finishes — including runs that end parked or needs_human with nothing delivered. A receipt minted from an undelivered draft is a dishonest artifact: close it with an outcome stating receipts are re-minted only after the principal delivery decision.
- A 409 bounce-cap naming a row you already force-closed is a stale brake read, not a stuck brake: verify the stage in the ledger DB, then re-POST — the following attempt passes without a restart.
- **Inserting a helper function above a decorated FastAPI endpoint by string-replace swallows the route when the new function lands between `@app.post(...)` and the real handler** — the decorator then wraps the helper (live symptom: POST returns the helper's gate dict instead of running the lane, and the endpoint's query params suddenly read as missing). Anchor the insert on the bare `def` line or re-attach the decorator explicitly, and `sed -n` the route block to confirm decorator → handler adjacency before restart.
