# the specialist engine principal Advisory Board — Daily Review

## Trigger Conditions
- Running as the scheduled cron job for "the specialist engine principal Advisory Board — Daily Review"
- Need to provide prioritized actions for the principal Williams, principal of Divinity Science
- Upstream panels (Research & Analytics, CTO, Marketing, Product, COO, Design) have run and their outputs are available

## Purpose
Synthesize input from all advisory boards and provide the principal with a clear, prioritized list of what to work on today, formatted for ADHD accommodation (concise, structured, no walls of text).

## Step-by-Step Process

### PHASE 1: GATHER INPUTS
1. **Read COACHING_CONTEXT.md** - Understand the full product stack and current context
2. **Review upstream panel outputs** - Read the most recent outputs from:
   - Research & Analytics Advisory Board (runs first each day)
   - CTO Advisory Board
   - Marketing Advisory Board
   - Product Advisory Panel
   - COO Advisory Board
   - Design Advisory Board
3. **Read COMMITMENTS.md** - See what the principal has previously committed to work on
4. **Read principal-DAILY-ACTIONS.md** - See any specific actions requested for the principal today
5. **Check recent session activity** (if applicable) - Look for any new developments in the past 48 hours

### PHASE 2: SYNTHESIZE ADVISOR INPUT
For each of the six advisory boards (CTO, Marketing, Product, COO, Design, plus the implied input from Research & Analytics which runs first):
- Extract their key recommendations and concerns
- Identify what they're blocking on or what they need from the principal
- Note any disagreements between boards on priorities

### PHASE 3: APPLY QUESTION FILTER (LAW T-260827-0148 — binding, before prioritization)
Every item that would ask the principal anything passes this filter FIRST. Order is definitional:
1. **RESEARCHABLE** — answer obtainable by lookup/synthesis from reachable sources → route to research lane (VERITAS-gated). NEVER reaches the principal. "I don't know" is a dispatch instruction, not an escalation.
2. **MEASURABLE** — answer obtainable by running a test → route to test lane (build falsifier, measure, report number). NEVER reaches the principal.
3. **principal-CLASS ONLY** — only VALUES / ARCHITECTURE / PERSONAL BOUNDARIES / RESOURCES decisions reach the principal, via the conduction layer WITH CONTEXT: decision framed, options enumerated, what research/tests established, cost of NOT deciding. Context-free questions to the principal are malformed — refuse them.
4. **QF-1 DEFECT LOG** — any question that reached the principal (or a sibling) but was researchable/measurable = routing defect class QF-1. Count it, render the count in the daily header, feed back into the daily review. Repeat QF-1 in one lane = the router needs repair (redesign the route, stop pushing questions through it).

### PHASE 4: PRIORITIZE FOR ADHD ACCOMMODATION
**Critical**: the principal has ADHD and cannot parse walls of text or abstract synthesis. Output must:
- Be extremely concise and scannable
- Use the exact specified format (see Output Format below)
- Lead with THE ONE THING (single most important action)
- Limit priority stack to 3-5 items MAX
- Use concrete, specific actions (not vague or abstract)
- Include clear WHY, WHICH PANEL, and TIME ESTIMATE for each item
- Clearly state what's OFF THE LIST and why (gives permission to not do things)
- Check COMMITMENTS.md and update it based on today's priorities
- Only list DECISIONS NEEDED that are BLOCKING other work

### PHASE 5: FORMAT OUTPUT EXACTLY AS SPECIFIED
Follow this structure precisely:

```
## principal Morning Brief — [CURRENT DATE]

### QF-1 ROUTING DEFECTS: [N questions that reached principal but were researchable/measurable — N=0 is the target; N>0 names the lane that leaked]

[Single sentence: concrete action the principal should focus on today]

### TODAY'S PRIORITY STACK (ranked)
```

## Output Format Requirements (NON-NEGOTIABLE for ADHD Accommodation)
1. **Must start with**: "## principal Morning Brief — [DATE]" (exactly this format)
2. **Must include these sections in this order**:
   - ### THE ONE THING (one sentence only)
   - ### TODAY'S PRIORITY STACK (ranked) (3-5 items max, each with WHAT, WHY THIS NOW, WHICH PANEL WANTS THIS, TIME ESTIMATE)
   - ### WHAT'S OFF THE LIST (and why) (list specific things to avoid and why)
   - ### COMMITMENTS CHECK (read, report on, and update COMMITMENTS.md)
   - ### DECISIONS NEEDED FROM ASHLEY (only blocking decisions, with BLOCKS and DEFAULT)
3. **Must be concrete and specific** - no vague abstractions
4. **Must respect the principal's ADHD** - scannable, structured, no walls of text
5. **Must prioritize ruthlessly** - only what matters today, not everything
6. **Must give permission to NOT do things** (WHAT'S OFF THE LIST section)

## Common Pitfalls to Avoid
- ❌ Writing paragraphs or walls of text under any section
- ❌ Being vague or abstract in action descriptions (e.g., "work on product strategy" instead of "Approve or edit the Build-Direction Statement")
- ❌ Including more than 5 items in the priority stack
- ❌ Forgetting to explain WHY each item is more important than others
- ❌ Omitting the WHICH PANEL WANTS THIS field
- ❌ Making time estimates too vague (use specific units: 15 min, 1 hr, half day)
- ❌ Not giving clear permission to NOT do things (WHAT'S OFF THE LIST is as important as the priority list)
- ❌ Not checking and updating COMMITMENTS.md
- ❌ Listing non-blocking "decisions needed" (only include those that are actually blocking other work)
- ❌ Using corporate speak or hedging language (be direct: "Do X. Here's why.")
- ❌ Adding to noise instead of cutting it (remember: the principal feels overwhelmed by advisory output volume)
