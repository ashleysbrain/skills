## Detailed Field Specifications

### THE ONE THING
- Must be exactly one sentence
- Must be concrete and specific (not vague or abstract)
- Should represent the single highest priority action for the day
- Example: "Approve or edit the Build-Direction Statement to unblock the principal's team and enable Better Sleep product development."

### TODAY'S PRIORITY STACK
- Must contain 3-5 items maximum (respecting ADHD constraints)
- Each item must follow this exact format:
  - **[ACTION]**: Specific, concrete action (not vague or abstract)
  - **Impact**: Explanation of why this action is important
  - **Source**: Which advisory board flagged this (principal, Product, Marketing, CTO, COO, or Design)
  - **Time Estimate**: Rough guess (e.g., 15 min, 1 hr, half day)
- Items must be ranked in true priority order (most important first)
- Example: "1. **Approve or edit the Build-Direction Statement** — Impact: Unblocks the principal's entire team after 9 days of stall, enabling Better Sleep product build — Source: COO Board — Time Estimate: 15 min"

### WHAT'S OFF THE LIST (and why)
- List items that people might expect the principal to do but she should NOT focus on today
- For each item, explain why it can wait (e.g., depends on other priorities, not blocking, can be deferred)
- This is as important as the priority list - it gives the principal permission to not do certain things
- Example: "- **Working on Wave Coaching or Concierge MVP features**: Better Sleep is the first product to ship per principal-DAILY-ACTIONS.md; focus resources there first."

### COMMITMENT CHECK
- Must reference the current state of COMMITMENTS.md
- Should indicate which items are being moved to completed, kept active, flagged as stale/scratched, or added as new
- Must specify that COMMITMENTS.md will be updated with these changes

### DECISIONS NEEDED FROM ASHLEY
- Only list decisions that are BLOCKING other work (not nice-to-know questions)
- Format: "- **[DECISION]**: What she needs to decide — Blocks: [what work is waiting] — Default IF NO ANSWER: [your recommendation]"
- If no blocking decisions exist, this section can be omitted or state "No blocking decisions required today"

## Formatting Rules
- Use exactly the markdown format shown above with the triple dashes (---) at start and end
- Do not use em-dashes or phrases like "Furthermore/Moreover" (AI telltales to avoid)
- Be direct and conversational - no corporate speak
- Each item in the priority stack must be numbered
- Time estimates should be realistic ranges (15 min, 30 min, 1 hr, half day, etc.)
- Source must be one of: principal, Product, Marketing, CTO, COO, or Design (advisor names can be used for more specificity if known)
