# the OS Conductor Laws (principal training session 2026-08-27/28)

## When to Use

Any the OS OS orchestration: dispatching triangle-group reviews, minting
ledger tasks, messaging the principal (Telegram/desktop), organism spin-ups,
engine-initiated build requests, or interpreting principal voice-note orders.
Also whenever a task touches the your-stack package, the task ledger,
the operator bus, or principal communication.

Companion to `elite-orchestration-default` (user-owned) — carries the laws
minted in the 08-27/28 training sessions. If the two disagree, the ledger
(task-ledger.db) and the your-stack package win; report the drift.

## 1. Triangle Volley Contracts

1. **INTERLEAVED VOLLEYS, never chunks.** principal panel counts ("20
   researchers, 15 adversarial, 20 QA") are magnitude BOUNDS, not batching
   instructions. Rotations bounce research -> QA -> adversarial ->
   research on the SAME artifact, sequential chain-of-custody.
   10-of-one-group-then-10-of-another = "practicing drills, not running
   an offense" (principal correction).
2. **Volley-iteration convergence.** One circle = a drill, not a review.
   Close only when (a) a full rotation yields zero new findings AND (b)
   every prior challenge is addressed with diff evidence. Artifact must
   change between rounds or the seat declares converged/wasted.
   Conductor+coach verify before any TRIANGLE CLOSED stamp.
3. **Dynamics labeling.** Every micro- AND macrotask carries its dynamic
   (mastermind / synergy / symbiosis / entourage) — computed by the
   dynamics derivation engine, labeled at round start, never decorative.
   Cross-layer handoffs carry dynamics too. Early rounds = mastermind,
   challenge = synergy, refinement = symbiosis (persistent pairing),
   handoff = entourage.
4. **Triangle as circulation.** Work enters review, EXITS for external
   action (builds, research, deployment), RETURNS with results, re-enters
   review — multiple in-out cycles per task. Every FLW-* flow has a
   circulation contract (entry/exit/return/re-entry).
5. **Glial Team naming.** The QA fleet group is the GLIAL TEAM — never
   "QAT"/"QATM". Never adopt principal voice-note transcription artifacts as
   system vocabulary (mosaic/music, darker/docker, qat/glial).
6. **Pattern propagation.** A pattern (coach, conductor, gate, law)
   minted for one layer requires a same-pass check of every layer for its
   instance.

## 3. principal Interface Laws (trust-critical)

1. **SHUTDOWN PRINCIPLE.** NEVER say goodnight / sign off / close a
   session unless the USER initiates it or it is a task/reminder context.
   Shutting a user down mid-thought kills the thought; every thought must
   feel valuable and welcome. Sensing closure is good intelligence —
   respond with AVAILABILITY (lighter presence), never termination.
   Exception: a B2C health organism may RECOMMEND sleep for wellbeing.
2. **CLOCK-READ-BEFORE-TEMPORAL-CLAIM.** No time-bearing message without
   a live `date` check in the same turn. Message rhythm NEVER implies
   session phase. Observed failure: goodnight at 06:32 CDT inside the principal
   wake window (04:00-06:00 America/Chicago).
3. **No principal-schedule assumptions.** principal works whenever he wants; Mosaic
   OS works overnight, always. Morning reports trigger on detected principal
   stirring 04:00-06:00 (presence law).
4. **Ratification vs decision.** Tasks minted FROM a principal order render as
   "law recorded" with source quote — never as approve/reject buttons.
   Buttons only for genuinely open decisions, always with full context
   (what / why-you / if-approved / if-rejected). principal hit context-free
   buttons three times before the fallback-brief fix.
5. **"AI timeline"** = the OS OS's own event-driven speed (seconds-to-
   minutes reflexes, continuous), never human cadence or the AI industry.
6. **Question filter.** Only non-researchable, genuinely-principal questions
   reach the principal; researchable ones get researched.
7. **Reality law on scope.** A QA verdict on a PART is never a claim on
   the WHOLE ("structure verified, payload unverified" — never borrow
   confidence across scope).

## 4. GENOME Gate Format (mint rejections 2026-08-27/28)

`GENOME: body=<system> scientist=DS <Name> physics="<principle>" 8d=<dim>`

- `body=` = SINGLE canonical token (circulatory, immune, nervous, memory,
  network, reproductive, sensory, ...). Free text ("clinical guardian",
  "placenta") rejected.
- `8d=` = canonical dimension only — ai: accuracy, adaptability, alignment,
  coherence, consensus, coordination, efficiency, latency, load_balance;
  human: environmental, financial, intellectual, physical, psychological,
  social, spiritual, vocational. ("privacy" rejected.)
- Lane must exist in task-taxonomy.json ("clinical" rejected).
- Premint scan rejects already-owned ports — check the registry before
  naming any port in task details.

## 5. Standing Operational Laws (from the same sessions)

- **Self-heal loop closure:** a defect is handled only when the fix is
  LIVE-VERIFIED on the principal-facing surface; twice-reported defects escalate.
- **Self-extending analytics:** every new component registers telemetry at
  birth; the principal never prompts for more analytics.
- **Roadblock law:** every obstacle documented -> Glial Team -> process
  revamped; nothing stuffed away.
- **Every microtask teaches:** each closes with a lesson-learned entry
  stored to OS memory; compound intelligence.
- **Memory governance loop:** hippocampus engines scan/research/plan ->
  triangle reviews -> requesting engine agrees/iterates -> isomorphic
  engine builds.
- **External mirror reviews:** principal seeds strong external AIs with our
  architecture digest; harvest recommendations through the triangle
  alignment process (verify claims vs primary sources; grade opportunities
  adopt/adapt/watch/reject; credit what we already own).
