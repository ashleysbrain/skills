# QAI Health Engine Source Brief

Source: the user's original morning voice memo about the QAI health engine.

## Durable requirements captured from the brief

- The user wants the first deliverable to be a *panel of top five agents/personas* before any summary or research synthesis.
- Persona presentation must be **full-stack**, not half credentials: exact institutions, qualifications, certifications/licenses, senior roles, and methodology lineage.
- The health-engine request is **not** a persona-panel request. It is a separate engineering/scoring task.
- The engine should be **self-healing** and **self-sustaining**.
- It should monitor the agent via **behavioral/telemetry evidence**, not self-report.
- It should catch drift, skew, odd behavior, and broken algorithms early.
- It should expose analytics so the user can steer the agent based on observable health signals.
- It should use an **eight-dimensions-of-wellness** framing adapted to agent health.
- The scoring model should remove self-assessment bias and rely on behavior-first metrics.
- The user asked for the panel to be shown first and wants to approve it before moving into the summary or research phase.

## Usage note

Use this reference when building or reviewing QAI/Cubit health-engine work, especially when deciding whether to route a request to persona selection or to scoring/engineering.
