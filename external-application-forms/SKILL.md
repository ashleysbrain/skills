# External Application Forms

## When to Use
- The principal pastes a link to a program application, interest form, fellowship, accelerator, or award submission and asks to qualify or fill it
- Any external form with free-text answers that represent the company or founder
- NOT for: customer onboarding forms, internal forms, or purchasing flows

Class-level skill for drafting external program applications, interest
forms, fellowships, accelerator/award submissions, and similar
representative forms on behalf of the principal. The deliverable is a
qualification verdict plus paste-ready answers that survive diligence;
submission itself is usually physically the principal's.

## Procedure (in order)

1. **Deliver the qualification verdict as its own step.** When the ask
   is conditional ("IF I qualify"), read the live form plus the program
   page, find the eligibility category that fits (e.g. an
   Industry/Corporate Research track), and state the verdict with the
   evidence BEFORE drafting anything. Never draft first and fold the
   verdict into the delivery.
2. **Extract fields from the live form**, not from memory or a prior
   screenshot: field sets, options, and required markers change. Read
   every field once end-to-end before answering any of them.
3. **Probe public presence before citing it.** Every URL that will
   appear in an answer gets a live reachability check (profile, company
   page, abstract pages, owned domains). Cite only reachable anchors;
   a dead link in an application is an unrecoverable first impression.
4. **Build a fact ledger before writing.** Established facts vs current
   work ("building," "studying") vs ambition. Every credential written
   at its exact verified level.
5. **Draft each answer strategic-tight.** Name BOTH the research
   organism and the operating system in the flagship free-text answer;
   the pairing is the differentiation and either one alone reads as a
   side project. Describe capabilities by effect, not mechanism. Long
   free-text fields land near 150 words: every sentence carries a fact
   or an intrigue, none carries process narration. Standing ruling on
   the register: "Keep it strategic don't blab."
6. **Run the full gate BEFORE the first delivery.** A paste-ready draft
   handed to the principal is a delivery, not an internal iteration; she
   pastes what arrives. Minimum three elite-brain iterations from
   different specialists (voice pass, architecture-encryption pass,
   hostile factual pass), then the AI-tell scanner, then deliver with
   gate receipts (banned phrases, dash count, entity mentions, word
   count). Fixing gates after her correction means the pipeline was
   skipped.
7. **Flag principal-owned actions and judgment calls.** Fields that bind
   identity (signed-in account, signature) are physically the principal's:
   deliver everything else paste-ready and name the binding step.
   Organizational/data decisions (commercial vs non-commercial, data
   sharing) are principal calls: give a recommendation with the tradeoff,
   never silently choose.
8. **Re-issue the full packet when the principal hands the form to a teammate.**
   When the principal says someone else will help fill it out, deliver the
   complete field-by-field answer set again as ONE self-contained
   message with the live form URL at the top. The teammate has none of
   the chat context; a packet missing the link or any field forces the
   principal to relay twice. Keep the one-line strategic frame at the bottom
   for why the application matters.

## Pitfalls

- Delivering an ungated draft because "it's just a draft" is the
  canonical failure; the draft becomes external text the moment it
  leaves the chat.
- After ANY in-chat correction to an answer (fact level, wording, a
  credential notch), re-deliver the COMPLETE revised answer, never just
  the changed line — the principal pastes the latest message wholesale, and a
  delta reply forces her to splice two messages at paste time.
- A second delivery attempt in the same chat can corrupt mid-send
  (garbled repetition block after the first paragraphs). When a message
  visibly malforms, say so in one line and immediately re-send the clean
  full text — never let the corrupted copy stand as the latest message.
- Mechanism detail (dimension counts, dataset-construction methods,
  invariance vocabulary) is moat-adjacent blab; say what the capability
  DOES, not how it is built internally.
- Credential inflation by one notch ("selected for presentation at"
  becoming "presented at") fails diligence; selection, presentation,
  and attendance are three distinct claims. Write the one that is true.
- Do not guess eligibility categories from the program's marketing
  page; the form's own option list is the authority.
- If a flagship answer names internal architecture, rewrite to public
  technology vocabulary before the factual pass; the encryption pass
  and the voice pass catch different leaks, run both.
